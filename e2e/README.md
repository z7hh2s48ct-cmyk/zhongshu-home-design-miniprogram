原 `/tmp/zs-e2e.mjs` 不在 Git 历史和当前机器中。本目录依据 `项目文档/10-开发进度与完成情况报告-V1.0.md` 重建旧 37 项链路，追加 T10-17 的 17 项预算三端检查，再追加 T14 的 4 项账号覆盖价检查，当前共 58 项；不声明与遗失脚本逐字一致。

## 运行

先以 `local,pg,zsdev` 启动后端，再从仓库根目录执行：

```bash
node e2e/zs-e2e.mjs
```

查看检查点或仅做离线结构校验：

```bash
node e2e/zs-e2e.mjs --list
node e2e/zs-e2e.mjs --validate
```

默认只允许访问 loopback，防止误写共享或生产环境。每次运行使用唯一微信 Stub code、预算地区、自定义模板、幂等键和业务备注；Runtime 产生的 PNG 在结束时逐文件清理。数据库业务记录依照审计要求保留，不以 SQL 绕过领域删除。CI 使用全新 Docker 卷，并在结束时销毁该卷。检查点总数取自脚本登记，不再硬编码旧 37 项口径。

预算链断言包含：管理端配置地区/标准价/自定义模板、用户导入参数和生成 48,202,000 分黄金预算、后台补项至 48,562,000 分、发布 48,000,000 分首版报价、调价发布 48,010,000 分二版报价、旧版本冻结、公开脱敏、无权限拒绝与幂等回放。

T14 覆盖价断言包含：0 元被拒、覆盖价 60,000 分生效且新测算 49,162,000 分（48,202,000 + (60,000−52,000)×120㎡）、基准价目录不可被用户改写、已保存预算冻结、恢复默认幂等并回 48,202,000 分、管理端可查 REMOVED 历史、缺价选项（208002）由覆盖价补齐并联动目录 AVAILABLE、覆盖价测算 47,362,000 分、解绑降级后三个接口均返回 1070001001。

环境变量样例见 `.env.example`。默认资产目录为系统临时目录下的 `zhongshu-assets`，它必须与 Java 的 `zhongshu.design.asset.storage-root` 一致。报告写入 `artifacts/e2e/latest.{json,md}`，该目录不入 Git，由 CI 作为制品保存。
