# T14 激活用户当地单价覆盖方案 V1.0

> 日期：2026-09-14  
> 定位：激活用户按账号覆盖预算单价（匹配当地成本）专项的设计正本；本文件只定义方案与合同，不代表已实现或已验收。任务拆分与验收标准见 [T14 任务清单](T14-激活用户当地单价覆盖任务清单与验收标准-V1.0.md)，动态状态统一登记 [项目状态看板](项目状态看板.md)。  
> 上游：[T10 预算模块最终修改方案](T10-预算模块最终修改方案-V1.0.md)、[T11 武汉市正式计价配置记录](T11-武汉市正式计价配置记录-2026-09-09.md)。本方案修订 T10 方案第 4.3 节"地区价格"的适用口径，不推翻其计价、精度与快照合同。

## 1. 需求来源与已确认口径

需求原文："用户激活码要能用于修改默认的地区预算中的单价，用于匹配当地的成本"。2026-09-14 用户逐条确认：

| 决策点 | 已确认口径 |
|---|---|
| 改谁的价 | **解读 B**：激活用户在"自己名下"覆盖单价，使自己的预算测算用当地成本价；平台默认价不变，其他用户不受影响。**不是**修改平台公共默认价，用户侧不开放任何写 `budget_item_price` 的通道 |
| 地区维度 | **不再做地区价格配置**。平台默认单价 = 武汉基准价（标准参考价，来源《2026预算公式培训上线.xlsx》，T11 已完成正式配置）；其他城市在此基准上由用户自行覆盖，不逐地区建价 |
| 生效方式 | 覆盖价**跟账号永久生效**，直到用户自行修改或恢复默认；不按次临时生效 |
| 触发资格 | 激活（unrestricted 会话）用户；激活码模型本身零改动，"覆盖单价"是激活后的一个业务能力，挂在现有门禁之下 |

被否决的口径（留档防回潮）：用户可写平台公共已发布价；渠道/代理激活码绑定地区价表；按次临时覆盖。

## 2. 目标与范围

**包含**：账号单价覆盖表与迁移；测算取价两层规则；快照来源标记；小程序目录可用性联动；小程序"我的当地单价"查询/设置/恢复默认；管理后台基准价语义收窄与覆盖只读查询；后端自动化与三端 E2E 扩展。

**不包含**：地区维度价格配置（含新增地区入口的继续开放）；渠道激活码模型扩展；管理员对外报价流程变更（对外报价仍为管理员职权，用户覆盖价不自动流入报价核定）；旧 LEGACY_RANGE 模型（`budget_rule_version` 无管理接口，维持现状）；免费/赠送标记（0 元）对用户开放；批量调价（整体系数）模式——如后续需要，在本合同上追加，不推翻。

## 3. 计价规则

### 3.1 两层取价

```text
某选项参与测算的单价 =
  1) 该账号的 ACTIVE 覆盖价（budget_account_price，若有）
  2) 否则基准地区已发布价（budget_item_price，status='PUBLISHED' 且在生效窗口内）
  3) 两者皆无 → MISSING_PRICE（行为与现状一致）
```

- 行金额、小计、总额的计算公式与 T10 第 5 节完全一致，仅"单价"来源多一层；金额仍由服务端按整数分、逐行 `HALF_UP` 计算并加总，不信任客户端任何金额。
- 覆盖价**不分地区**：`budget_account_price` 以 (账号, 选项) 唯一，不挂 region。基础参数页的"建造地区"字段保留为展示信息，不再驱动取价；测算流程仍按现状解析并校验 `regionCode`（取基准地区行），快照中的 `regionId`/`regionVersion` 继续记录，保持快照结构兼容。
- 基准地区 = 武汉（T11 已配置的唯一正式价格地区，code 以库中实际值为准）。价格读取固定落到该基准地区行；即使存在其他地区行或价格数据也不参与计价。

### 3.2 快照与不变量

- `pricing_snapshot` 每行新增：`priceSource`（`DEFAULT`｜`ACCOUNT_OVERRIDE`）；覆盖生效时另记 `accountPriceId` 与 `accountPriceVersion`。基准价的 `priceVersion`、`effectiveAt`、`expiresAt` 无论是否覆盖都照旧记录（覆盖场景下它是"被覆盖时的基准版本"，用于审计对账）。
- 维持 T10 既有不变量：已保存预算、历史版本、已发布报价冻结的 `unit_price_cents` 与快照**不因改价漂移**；覆盖价只影响之后的新测算。
- 同一选项在同一账号同一时刻最多一条 ACTIVE 覆盖价（部分唯一索引保证），改价 = 事务内 upsert，天然幂等。

## 4. 数据模型与迁移

迁移脚本：`后端程序/yudao-module-design/src/main/resources/db/migration/design/V20260914.215__t14_account_price.sql`（编号顺延当前 214）。

```sql
CREATE TABLE budget_account_price (
    id               BIGINT CONSTRAINT pk_budget_account_price PRIMARY KEY,
    tenant_id        BIGINT NOT NULL DEFAULT 0,
    account_id       BIGINT NOT NULL,
    option_id        BIGINT NOT NULL,
    unit_price_cents BIGINT NOT NULL
        CONSTRAINT ck_budget_account_price_unit CHECK (unit_price_cents > 0 AND unit_price_cents <= 100000000),
    reason           VARCHAR(500),
    status           VARCHAR(16) NOT NULL DEFAULT 'ACTIVE'
        CONSTRAINT ck_budget_account_price_status CHECK (status IN ('ACTIVE', 'REMOVED')),
    created_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
    version          INTEGER NOT NULL DEFAULT 1 CONSTRAINT ck_budget_account_price_version CHECK (version > 0),
    deleted          BOOLEAN NOT NULL DEFAULT FALSE
);
-- 同账号同选项同时刻仅一条生效覆盖；恢复默认置 REMOVED，保留历史可审计
CREATE UNIQUE INDEX uq_budget_account_price_active
    ON budget_account_price (tenant_id, account_id, option_id)
    WHERE status = 'ACTIVE' AND deleted = FALSE;
CREATE INDEX idx_budget_account_price_account
    ON budget_account_price (tenant_id, account_id) WHERE deleted = FALSE;
```

- `unit_price_cents` 上限对齐 `budget_item_price` 既有约束（0～1 亿分，即 0～100 万元），下限收紧为 >0（用户不允许 0 元，见 6.2）。
- 不外键强绑 `budget_option`，与库内其余表做法一致；服务层校验选项存在且参与公开目录。
- `account_id` 即 `identitySessionPort.requireUnrestricted(token).accountId()`，与 `budget_estimate.user_id` 同源。

## 5. 接口合同

App 端新增（挂在 `AppBudgetController` 同级新控制器，路径前缀 `/app-api/design/v1`，`@PermitAll` + 方法内 `requireAccountId` 非受限会话校验，与现有预算端点一致）：

| 方法与路径 | 入参 | 出参要点 |
|---|---|---|
| `GET /design/v1/budget/my-prices?regionCode=` | 基准地区码 | 分组逐选项：`optionId`、`label`、`unit`、基准价（分，缺价则 null）、`myPriceCents`（无覆盖则 null）、`priceSource`（`ACCOUNT_OVERRIDE`/`DEFAULT`/`MISSING`）、`reason`、`updatedAt` |
| `PUT /design/v1/budget/my-prices/{optionId}?regionCode=` | `regionCode` 必填查询参数（写前即校验，杜绝无效地区产生写入）；`{ unitPriceCents, reason? }`，`reason` 选填、≤500 字 | 覆盖后的该选项状态（含最新基准价与来源） |
| `DELETE /design/v1/budget/my-prices/{optionId}?regionCode=` | `regionCode` 必填查询参数 | 恢复默认，返回基准价视图 |

规则：

1. 三个端点统一 `requireUnrestricted`：受限会话（未激活）返回业务码 `1070001001`（ACCESS_GRANT_REQUIRED），无效 token 返回 401，与 `AppBudgetController.requireAccountId` 现状一致。
2. `PUT` 校验：选项存在、启用且属于公开目录的 STANDARD 项选项（CUSTOM_TEMPLATE 项不开放用户覆盖，维持后台补价流程）；`unitPriceCents` 为正整数且 ≤ 100000000；`reason` 长度上限。非法输入返回新增错误码 `BUDGET_ACCOUNT_PRICE_INVALID`。
3. `PUT` 对基准缺价选项同样有效（补价口径，见 6.1）；`DELETE` 幂等，无 ACTIVE 覆盖时直接成功。
4. 目录可用性联动：登录用户视角的 `publicOptions` 中，某选项"有覆盖价 **或** 基准已发布价"即 `AVAILABLE`；仅基准缺价且无覆盖时维持 `MISSING_PRICE`。实现为账号感知的目录变体，不改变未登录/管理端语义。
5. 不做限流以外的额外风控；`PUT/DELETE` 以 `@RateLimiter(keyResolver = ExpressionRateLimiterKeyResolver, keyArg = "#authorization")` 按会话 token（即账号）限流：60 秒 10 次，防止换参绕过默认按请求聚合的 key。

管理端新增（可选任务，见任务清单 T14-06）：`GET /admin-api/design/v1/budget/account-prices?accountId=`，`@PreAuthorize("design:budget:query")`，只读，支持按账号查覆盖清单；本期不做管理端干预（重置/清空留待客诉场景再开）。

## 6. 已定默认口径（含此前三个待定点）

1. **基准缺价可由用户补价**：有覆盖价即可参与测算并标 `AVAILABLE`，避免个别未配价选项把用户卡死；补的价进快照并标 `ACCOUNT_OVERRIDE`。若产品后续要求"仅覆盖已配价选项"，只需在 `PUT` 校验加一条，合同不变。
2. **0 元/免费不对用户开放**：覆盖价必须 >0；免费标记是管理员职权，避免用户以 0 元冒充完整预算，与 T10"不允许以默认 0 代替缺价"一致。
3. **建造地区字段保留**：输入页、快照结构不动，语义降为展示信息。
4. **管理端可见性**：本期做只读查询；不做干预操作。
