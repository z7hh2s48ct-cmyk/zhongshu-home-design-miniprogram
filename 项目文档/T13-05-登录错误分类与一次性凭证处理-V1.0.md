# T13-05 登录错误分类与一次性凭证处理 V1.0

日期：2026-09-09。所属批次：B1（微信身份与激活入口）。对应任务：T13 计划 §5 B1 表 T13-05。

验收标准（计划原文）：**区分无效/已使用 code、微信服务异常和配置错误；超时有限；不盲目重试一次性 code；不记录敏感请求 URL。**

本文是 B1 登录错误处理的**开发交付记录**，承继《T13-04 真实微信身份适配器》。它证明「code2session 各类失败已被分类并映射为不同错误码，且超时/不重试/URL 脱敏四条验收全部满足并被隔离测试覆盖」，**不**代表已在真实微信环境验收——真实验收属凭据依赖项，见 §8。

---

## 1. 目的与边界

- **目的**：T13-04 已把 code2session 的所有失败统一抛为 `WechatIdentityException`（携带微信数值 `errcode`），但登录链路对其**未加区分**——任何失败都冒泡为通用 500，前端无法据以给用户恰当提示、运维无法据以告警。本项为失败引入**四类分类**，并在 `AccountLoginService.login` 翻译为**四个独立的认证层错误码 + 用户可读文案**，同时守住「超时有限、不重试一次性 code、不记录敏感 URL」三条既有保证。
- **验收四要点 → 落点**：

  | 验收要点 | 落点 | 归属 |
  |---|---|---|
  | 区分无效/已使用 code、微信服务异常、配置错误 | `WechatLoginFailure` 四类 + `classifyErrcode` + `login` 翻译 | **本项 T13-05 新增** |
  | 超时有限 | `sendAsync().get(totalDeadline)` 有界总超时（建连+响应头+body 读取硬上限） | 承继 T13-04 |
  | 不盲目重试一次性 code | 应用层单次调用 + `disableRetryConnect=true` + `login` 失败即抛（测试断言 `times(1)`） | 承继 T13-04 + 本项强化 |
  | 不记录敏感请求 URL | 异常消息/日志净化（T13-04）+ `login` 只记 kind+errcode、绝不记 `e.getMessage()` | 承继 T13-04 + 本项 |

- **边界（本文不声称）**：真实微信 `errcode` 联调需正式凭据（§8）；本项不改任何环境默认装配、不改领域接口 `WechatIdentityPort`、不改前端页面代码（前端契约见 §6，交互收口属 T13-07）。

## 2. 设计决策：认证层错误分类（不入 §7.6 注册表）

- **为何用枚举分类而非字符串/errcode 匹配**：`errcode==null` 的**本地失败**（配置缺失、请求构建失败、请求超时、传输失败、响应解析失败、协议异常）无法仅凭 `errcode` 区分；对异常消息做字符串匹配则脆弱（上游文案变更即击穿）。故由适配器在**每个抛出点显式标注** `WechatLoginFailure`，`WechatIdentityException` 强制 `failure` 非空（`Objects.requireNonNull`），从类型层面杜绝「未分类失败」。
- **错误码段位（关键决策）**：四类码置于 `1-070-001-01x`「认证 / 会话层」子段，**刻意不入架构 §7.6 稳定错误码注册表**（`1-070-000-xxx` 段，由 `ZhongshuErrorCodeRegistryTest` 锁定为固定 21 个领域业务码、字段名 `isEqualTo`）。理由：微信登录失败属**认证传输层**，与既有 `IdentitySessionPort.ACCESS_GRANT_REQUIRED`（`1_070_001_001`）、会话 `401` 同层同理，非 §7.6 的领域业务规则。故以 `int` 码 + `new ServiceException(code, msg)` 承载（遵 `ACCESS_GRANT_REQUIRED` 先例），**不占用注册表、不改冻结的架构文档与跨模块合同测试**，改动半径收敛在 identity 模块内。
- **安全**：`CONFIG_ERROR` 的服务端根因（appid/appsecret 缺失或被微信判定非法、请求构建失败等）属内部配置问题，其 `clientMessage` **刻意泛化**（不回显任何配置细节），仅以独立错误码供运维告警与前端区分；四类 `clientMessage` 均为固定文案、不含任何动态敏感值（承继 T13-04：异常消息与日志已不含 URL/secret/code/session_key）。

## 3. 实现

### 3.1 `WechatLoginFailure` 枚举（新增）

`后端程序/yudao-module-identity/.../wechat/WechatLoginFailure.java`：四常量，各携 `code`（认证层码）+ `clientMessage`（用户可读文案）；`toServiceException()` 转译为 `new ServiceException(code, clientMessage)`，由 `GlobalExceptionHandler.serviceExceptionHandler` 渲染为 `CommonResult.error(code, msg)`（前端据此得 `error.code`/`error.msg`）。

### 3.2 `WechatIdentityException` 加失败分类（改）

新增 `final WechatLoginFailure failure` 字段 + 3-arg 构造器（`Objects.requireNonNull(failure, "failure 分类不得为空：每个失败点都必须显式归类")`）+ `getFailure()`；原 2-arg 构造器移除（唯一生产者是 `RealWechatIdentityAdapter`，已全部更新）。`errcode` 语义不变（微信原始码，本地失败为 `null`）。

### 3.3 `RealWechatIdentityAdapter` 标注分类（改）

12 个抛出点全部标注 `WechatLoginFailure`（**异常消息保持不变**，T13-04 的 18 用例零改动仍全绿）；新增 `private static WechatLoginFailure classifyErrcode(int)` 把微信 errcode 归入四类（映射见 §5）。T13-04 定型的健壮性逻辑（有界总超时、不重试、URL/凭据脱敏、cause-free 异常、构造期校验 base-url、`disableRetryConnect`、`RESPONSE_MAPPER` 排除 errmsg/session_key）**均未改动**。

### 3.4 `AccountLoginService.login` 翻译（改）

`codeToSession` 先于任何 DB 访问；用 `try/catch` 包裹，捕获 `WechatIdentityException` → 取 `getFailure()`：`CONFIG_ERROR` 以 `log.error` 告警运维、其余 `log.warn`（**只记失败分类名与数值 errcode，绝不记 `e.getMessage()`**），随后 `throw failure.toServiceException()`。翻译发生在触库之前，故失败登录**不解析/新建账号、不签发会话、不重试**（一次性 code 由客户端重新 `wx.login` 取新 code）。

## 4. 四类错误码表

| 分类 | 错误码 | 客户端文案 | 触发条件 | 日志级别 |
|---|---|---|---|---|
| `INVALID_CODE` | `1070001010` | 微信登录凭证已失效，请重新登录 | errcode 40029；空 code（防御性，HTTP 层 `AppAuthLoginReqVO` 的 `@NotBlank` 已先拦为 400） | WARN |
| `CODE_ALREADY_USED` | `1070001011` | 微信登录凭证已被使用，请重新登录 | errcode 40163（oauth_code 已使用） | WARN |
| `WECHAT_SERVICE_ERROR` | `1070001012` | 微信服务暂时不可用，请稍后重试 | errcode -1/45011/40226/其它未知码；非 200；超时（有界总时限 / 至响应头）；传输失败；解析失败；响应空 / 缺 openid | WARN |
| `CONFIG_ERROR` | `1070001013` | 登录服务暂时不可用，请稍后重试或联系支持 | appid/appsecret 缺失（本地校验）；请求构建失败（如非正 `read-timeout-ms` 致 `HttpRequest.timeout` 抛 `IllegalArgumentException`）；errcode 40013/40125/41002/41004 | **ERROR**（告警运维） |

> 四码互不相同、均 `> 1_070_000_999`（落在 §7.6 注册段位之外）；`CONFIG_ERROR` 文案泛化，不含 appid/secret/errcode 细节。
>
> **构造期校验 vs 登录期分类**：base-url 非法（scheme/host 不合法或含 query/fragment）由 `RealWechatIdentityAdapter` 在**构造期**即抛 `IllegalArgumentException` 快速失败（T13-04：启动暴露，绝不推迟到携带 secret+code 的请求期），**不经登录期 `CONFIG_ERROR` 分类**；登录期真正触发「请求构建失败 → `CONFIG_ERROR`」的是非正 `read-timeout-ms` 等构建期参数问题（`WechatLoginFailureClassificationTest` 以 `read-timeout=-1` 确定性覆盖）。

## 6. 客户端契约（前端消费，交互收口属 T13-07）

- 前端 `request.js` 把后端 `CommonResult.code/msg` 映射为 `error.code`/`error.msg`；`/auth/wechat-login` 的非 401 错误直接抛出（不触发 token 刷新重试）。
- `auth/index.js` 以 `wx.showToast` 显示 `err.msg`——四类失败各得恰当文案（如「微信登录凭证已失效，请重新登录」）。
- **一次性 code 语义**：任一类失败后，客户端应重新 `wx.login` 取**新** code 再试，**绝不自动重放同一 code**（重放只会得到 `CODE_ALREADY_USED`）；服务端亦不重试。
- 本项**不改前端代码**：错误码/文案经既有 `error.code`/`error.msg` 通道天然生效；前端激活入口交互收口（如按 code 分流「重新登录」引导）见 T13-07。

## 7. 隔离测试（无真实消费，默认构建即运行）

新增 2 个测试类（identity 模块），全程无真实微信调用、无 PG：

### 7.1 `WechatLoginFailureClassificationTest`（15 用例，全绿）

指向 T13-03 `FakeHttpServer`（`127.0.0.1` 临时端口），直接 `new` 适配器，专注验证**每个失败点的 `getFailure()` 分类**（与 T13-04 `RealWechatIdentityAdapterTest` 覆盖消息/无 cause/不泄密**互补**）：

- **枚举契约**：四码 ∈ `[1_070_001_010, 1_070_001_013]`、互不相同、`> 1_070_000_999`（在注册段之外）、`clientMessage` 非空、`toServiceException` 忠实携带 code+message；
- **errcode → 分类**：40029/40163/40013/40125/41002/41004/-1/45011/40226/未知码，逐一断言 `getFailure()` 与 `getErrcode()`；
- **本地失败（errcode==null）→ 分类**：空 code=`INVALID_CODE`；空 appsecret / 空 appid / 请求构建失败（非正 `read-timeout` 致 `HttpRequest.timeout` 抛 `IllegalArgumentException`）=`CONFIG_ERROR`；非 200 / 畸形 JSON / 空响应 / 传输失败 / 总时限超时 / 至响应头超时（`HttpTimeoutException`）/ 线程中断=`WECHAT_SERVICE_ERROR`；缺 openid=`WECHAT_SERVICE_ERROR`（`errcode` 保留为 0）；**中断分支另断言 `cancel` 释放底层交换且恢复线程中断状态**（codex round-1 P2：补齐请求构建失败 / 中断 / 至响应头超时三个此前未断言分类的抛出点）；

## 8. 真实验收（凭据依赖，本文不执行）

四类错误的真实触发需正式小程序 `AppID`/`AppSecret` 与真机 `wx.login`：置 `ZHONGSHU_IDENTITY_WECHAT_PROVIDER=real` + 注入 `ZS_WX_APPID`/`ZS_WX_APPSECRET`，用**过期 / 重复**的临时 code 走 `/design/v1/auth/wechat-login`，核验分别返回 `1070001010`/`1070001011` 与恰当文案、`session_key`/URL 不出现在任何响应/日志；再故意置错 secret 核验返回泛化 `1070001013` 且服务端 `ERROR` 级告警。**本文只交付「分类已实现、隔离测试通过」，不声称真实渠道已验收。**
