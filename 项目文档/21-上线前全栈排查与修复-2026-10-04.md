## 二、已修复问题

### P0-1 生产环境接口文档（Swagger / Knife4j）可匿名访问

- **文件**：`后端程序/yudao-server/src/main/resources/application-prod.yaml`
- **问题**：底座 `application.yaml` 中 `springdoc.api-docs.enabled` 与 `knife4j.enable` 默认为 `true`，而 `prod` profile **从未覆盖**。安全链 `YudaoWebSecurityConfigurerAdapter` 对 `GET /*.html` 放行，导致 `/swagger-ui/index.html`、`/doc.html` 在生产可被匿名打开，对外暴露全部接口结构。
- **修复**：在 `application-prod.yaml` 显式关闭 `springdoc`（api-docs / swagger-ui）与 `knife4j`。关闭后 `YudaoSwaggerAutoConfiguration` 因 `@ConditionalOnProperty(matchIfMissing = true)` 不再装配。临时排查可用 `--springdoc.api-docs.enabled=true` 显式开启。

### P0-2 部署脚本激活了不存在的 `development` profile

- **文件**：`后端程序/script/shell/deploy.sh`
- **问题**：`PROFILES_ACTIVE=development`。本项目**没有** `application-development.yaml`（仅 local / dev / pg / prod / zsdev）。若按该脚本部署，后端会以「无任何环境特定配置」状态启动：数据库、Redis、各 provider 密钥全部缺失，且**不会**收敛 swagger、**不会**关闭 mock 登录。属严重资损/越权风险。
- **修复**：改为 `PROFILES_ACTIVE=pg,prod`，与 `application-prod.yaml` 顶部 RG1/R06 约定及《18-正式环境部署指南》2.4 的 systemd `ExecStart` 保持一致。

### P0-3 后端 `.env` 的小程序 AppID 与发布工程不一致（登录会失败）

- **文件**：`后端程序/.env`
- **问题**：`ZS_WX_APPID=wx5753299f05a5c138`，而 `前端程序/project.config.json`、`前端程序/miniprogram/project.config.json`、`.env.example`、`release/release-v1-2-6/release-manifest.json`、《18-正式环境部署指南》**全部**为 `wxfa0a79d4e68cdb80`。AppID 不一致会使 `code2session` 直接失败 → 小程序无法登录。
- **修复**：对齐为 `wxfa0a79d4e68cdb80`，并注明依据。

### P1-1 后端跨域配置全开（`allowedOriginPattern("*")` + 凭证）

- **文件**：`后端程序/yudao-framework/yudao-spring-boot-starter-web/.../YudaoWebAutoConfiguration.java`
- **问题**：`setAllowCredentials(true)` 搭配 `addAllowedOriginPattern("*")`，任意站点均可携带凭证跨域调用接口（框架模板默认值）。
- **修复**：改为可配置白名单 `yudao.web.cors.allowed-origin-patterns`（逗号分隔），**默认仍为 `*`** 以不影响本地开发；`application-prod.yaml` 中默认留空（fail-closed，不放开任何跨域来源）。管理后台经 Nginx 以 `/admin-api` 同源代理、小程序不走浏览器 CORS，故生产留空是安全的；若后台确为跨域部署，填入实际域名即可。
- **已验证**：`./mvnw -o -pl yudao-framework/yudao-spring-boot-starter-web -am compile` 编译通过。

### P1-2 小程序 `config.js` 环境标识与域名错配

- **文件**：`前端程序/miniprogram/utils/config.js`
- **问题**：`apiBase` 已指向生产域名 `https://api.zszhj.com`，但 `env: 'dev'`。`utils/assets.js#fetchAssetDataUrl` 依据 `config.env !== 'dev'` 决定是否走开发内容端点，错配会让生产误走开发分支（静默降级而非快速失败）。
- **修复**：`env` 改为 `'prod'`，与构建脚本 `scripts/build-release.js` 生成发布包时的取值（第 61 行固定写 `env: 'prod'`）保持一致；补齐环境切换说明注释。
- **已验证**：`node --check` 语法通过；`release-v1-2-6` 产物本就是 `env:"prod"`，源文件与产物现已一致。

### P2-1 管理后台页面品牌信息残留（芋道模板）

- **文件**：`管理后台/index.html`
- **问题**：`meta keywords/description` 仍为「芋道管理系统…」，与产品品牌不符（影响分享/SEO 呈现）。
- **修复**：替换为众墅之家描述；`<title>` 保持 `%VITE_APP_TITLE%`（由环境变量注入，正确）。

### P2-2 后端 Dockerfile JDK 版本漂移

- **文件**：`后端程序/yudao-server/Dockerfile`
- **问题**：基础镜像 `eclipse-temurin:21-jre`，而 `.java-version`、`pom.xml`（`java.version=17`）、《部署指南》均为 Java 17。
- **修复**：统一为 `eclipse-temurin:17-jre`，消除运行时版本差异。

### P2-3 管理后台临时脚本残留

- **文件**：`管理后台/scripts-tmp-del.cjs`、`scripts-tmp-del3.cjs`
- **问题**：一次性补丁脚本（向各业务页批量注入删除功能），已完成使命，且未被 `package.json` 或任何文件引用。
- **修复**：移入 `管理后台/.trash-cleanup-2026-10-04/`（保留可回溯，未直接删除）。确认无需后可整体删除。

### 附：修复过程中发现并消除的次生缺陷

- **YAML 重复顶层键**：向 `application-prod.yaml` 追加 `yudao:` 时与该文件已有的 `yudao:` 冲突。SnakeYAML 取后者会**静默丢弃**原有的 `yudao.security.mock-enable: false`（生产将保留模拟登录后门）。已合并为单一 `yudao:` 节点，并用 PyYAML 校验顶层键唯一：`spring, yudao, zhongshu, management, springdoc, knife4j`。
