## 1. 目的与状态

本文交付 **T13-30 后半（真实资金验收）的脚手架**——把「真实支付→到账→整单退款→冲正→净额≈0」的验收动作，以**三层门禁的可执行骨架** + **脱敏证据留存机制** + **runbook** 预置到位，使外部前置（商户号/凭据/回调域名/书面批准）就绪后，团队只需把骨架方法体内的 TODO 替换为真实驱动即可执行，**不必从零搭建验收框架**。

**当前状态：骨架已就位，真实验收未执行**（外部前置未就绪，见 §2）。脚手架本身**默认绝不运行、绝不发起任何真实资金动作**。

## 3. Runbook（外部前置就绪后执行）

对应 `WechatPayRealAcceptanceTest` 三个骨架方法体内的 TODO：

1. 以 `@SpringBootTest` 启动全上下文，`zhongshu.commerce.payment.provider=real`（`RealServiceWiringPolicy` 校验五键通过，否则启动即失败）。
2. `RechargePaymentService.createOrder(userId, planId, idempotencyKey, openid)` 建 ¥0.01 测试单（openid 来源会话上下文，禁客户端传入）。
3. `getPayParams` → 真实小程序/JSAPI 拉起支付 → 真实付款 1 分。
4. 微信 `/design/v1/payments/wechat/notify` 回调 → `handleNotification` 先落 `payment_notification_inbox` 再快速应答 → `processPaymentFact`。
   - **断言**：`payment_transaction.channel='WECHAT'`、`merchant_id` == 真商户号（**非** `'stub-merchant'`）、`amount_cents` == 1、`payment_state='PAID'`、到账点数正确。
5. 对该已 `PAID` 测试单发起整单退款：`POST /recharge-orders/{orderId}/refund-requests`（需 `PAYMENT_RECONCILE` 权限）。
6. `WechatPaymentAdapter.requestRefund` → 微信 `/refund-notify` 回调 → `handleRefundNotification` → 查单收口 `queryRefund`。
7. 点数冲正（`PointReversalState`）与预留释放。
   - **断言**：`refund_order.channel_state='SUCCEEDED'`、退款金额 == 原支付金额（整单）、point reversal 完成；`PROCESSING`/`UNKNOWN` **绝不误判成功**（分派表 §8 红线 5）。
8. 核对净额：`net = 已收 1 分 - 已退 1 分 ≈ 0`（整单全额退款，允许渠道手续费差异，须书面记录口径）。

**执行开关（三层全开才会真实运行）**：

```bash
# 构建层：置空 excludedGroups 才纳入 real-acceptance 标签用例
mvn test -Dzs.test.excludedGroups= \
  # 用例层 + 金额/批准层：三个环境变量缺一不可
  # ZS_REAL_ACCEPTANCE=true
  # ZS_REAL_ACCEPTANCE_AMOUNT_CENTS=1        （硬上限 1 分，超过即 abort）
  # ZS_REAL_ACCEPTANCE_APPROVAL_REF=<审批单号/邮件主题/IM 记录链接>
```

> 三层门禁任一未开，`WechatPayRealAcceptanceTest` 整体禁用或 `Assumptions.abort`，**绝不发起真实支付/退款**。凭据（APIv3/私钥/证书）经部署环境带外注入，**绝不**写进命令行、`.env.example`、日志或本文。

## 4. 脱敏证据模板

真实验收的每一步用 `RealAcceptanceEvidence` 记录证据，`render()` 输出可直接粘贴到本模板。**铁律 1 同样约束证据**：证据会进验收记录/PR/issue 附件，夹带凭据等同泄露。

### 4.1 允许留存的字段（业务事实）

| 字段 | 示例 | 来源 |
|---|---|---|
| `requestId` | `req-20260911-0001` | 本次验收批次标识 |
| `testOrderNo` | `test-order-0001` | 本地商户订单号（`out_trade_no`） |
| `channelTransactionId` | `42000012342026091100...` | 微信支付订单号（`transaction_id`） |
| `amountCents` | `1` | 支付金额（分） |
| `paidAt` | `2026-09-11T02:00:00Z` | 支付完成时间（ISO-8601 UTC） |
| `refundId` / `channelRefundId` | `refund-1` | 本地退款单号（`out_refund_no`） |
| `refundChannelState` | `SUCCEEDED` | `refund_order.channel_state` |
| `netAmountCents` | `0` | 净额（分） |
| `screenshotRefs` | `artifacts/t13-30/pay-success.png` | 截图**路径引用**（截图本身也须先脱敏） |

### 4.2 禁止留存（`RealAcceptanceEvidence.redact()` 强制剥离，命中即 `[REDACTED]`）

- **APIv3 密钥**（`apiV3Key=` / `api-v3-key:` 键值对，及 32 位密钥明文）
- **商户私钥 / 证书**（`-----BEGIN ... PRIVATE KEY-----` / `-----BEGIN CERTIFICATE-----` PEM 块）
- **预签名 URL 签名参数**（`signature=` / `X-Amz-Signature=` / `X-Amz-Credential=` / `key=`）
- **`Authorization` 头 / `Bearer` 令牌**
- 证书序列号、任何完整请求 URL（可能含签名参数）

> 脱敏不变量由 **always-on 契约测试 `RealAcceptanceEvidenceTest`（8 例，进入默认 `mvn test`）** 持续锁定——**无需真实凭据**即可验证 `redact()` 剥离上述四类载体、`render()` 对 `notes`/`screenshotRefs` 两个自由文本入口强制净化。一旦有人放宽净化或新增未净化字段，该测试立即变红。

### 4.3 证据记录模板（复制填写）

```text

channel=WECHAT
requestId=<批次标识>
testOrderNo=<本地订单号>
channelTransactionId=<微信支付订单号>
amountCents=1
paidAt=<ISO-8601 UTC>
refundId=<本地退款单号>
channelRefundId=<本地退款单号>
refundChannelState=SUCCEEDED
netAmountCents=0
screenshotRefs=<脱敏截图路径,逗号分隔>

```

## 6. 与门禁/并发的关系

- 本脚手架属 **B4（支付）域**，与 B2 COS 提交**物理隔离**（不进 COS 提交）。
- 三个门禁层确保：即使误置 `ZS_REAL_ACCEPTANCE=true`，缺批准金额/批准引用仍 abort；即使三层全开，骨架仍停在「待接线真实上下文」——**外部前置就绪前，任何情况下都不会发起真实资金动作**（承 B4 真实资金高敏感门禁纪律）。
- always-on 的 `RealAcceptanceEvidenceTest` 不带门禁标签，随默认构建持续守护脱敏机制，与真实动作门禁刻意分离（护「机制不泄密」vs 护「真实动作不默认触发」）。
