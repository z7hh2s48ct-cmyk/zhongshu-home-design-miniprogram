## 1. 总体结论

**可以同步开发，但要区分「开发期」与「真实验收期」**：

- **开发期**（Day 0.5 – Day 2）：B4 与 B1（等 AppSecret 联调）、B2（COS）完全并行；B4 内部按关键路径 T13-21/T13-22 先落，再拆三条泳道并发推进 T13-23 ~ T13-30 前半。全程使用 T13-03 已就位的三类隔离手段（`FakeHttpServer` / Mockito SDK mock / Testcontainers PG），不触达任何真实微信端点。
- **真实验收期**（Day 2.5 – Day 3）：必须等 EXT-03（商户号 / APIv3 / 证书 / 回调 HTTPS 域名）到位、B1 真实身份联调完成，才允许进 T13-30 后半的一次支付 + 一次整单退款真实资金验收。

**SDK 选择决策（T13-21）**：底座 `yudao-dependencies/pom.xml` L84 已锁定 `com.github.binarywang:weixin-java-pay:4.8.6-20260825.155844`（WxJava 生态，支持 v3 API），本期**复用该依赖，不新增官方 `wechatpay-java` SDK**——符合 T13 计划 §9 "本期优先复用既有兼容依赖"原则，且与 yudao 底座 `SocialClientServiceImpl` 保持技术栈一致。`FakeHttpServer` 已预置微信支付 API 桩路径 `/v3/pay/transactions/jsapi`（`FakeHttpServerTest.java` L67），隔离测试开箱即用。

## 6. B4 登记到 REAL_MODE_REQUIREMENTS 的五个配置键（不含值）

按 T13-02 原则「只登记已被消费的键，不发明未消费变量」，与 B2 COS 五键对称：

| 键名 | 用途 | 消费点 |
|---|---|---|
| `zhongshu.commerce.payment.wechat.merchant-id` | 微信支付商户号 | `WechatPaymentAdapter` 构造期 → `WxPayConfig.setMchId()` |
| `zhongshu.commerce.payment.wechat.merchant-serial-no` | 商户 API 证书序列号 | `WechatPaymentAdapter` 构造期 → `WxPayConfig.setCertSerialNo()` |
| `zhongshu.commerce.payment.wechat.api-v3-key` | APIv3 密钥（回调通知解密用） | `WechatPaymentAdapter` 构造期 → `WxPayConfig.setApiV3Key()` |
| `zhongshu.commerce.payment.wechat.merchant-private-key-path` | 商户私钥文件路径（PEM） | `WechatPaymentAdapter` 构造期 → `WxPayConfig.setPrivateKeyPath()` |
| `zhongshu.commerce.payment.wechat.notify-url` | 支付回调 HTTPS URL | `WechatPaymentAdapter.createPrepay()` → `WxPayUnifiedOrderV3Request.setNotifyUrl()` |

**说明**：
- AppID 复用 B1 已登记的 `zhongshu.identity.wechat-appid`（微信支付要求商户号绑定的 AppID 与登录 AppID 一致）；B4 real 隐含要求 B1 real，跨端口约束由部署文档说明。
- `refund-notify-url`（退款回调）与 `platform-cert-path`（平台证书路径）在 WxJava SDK 中可通过 `notify-url` 派生与自动下载平台证书机制覆盖，本期不单独登记；如后续需要独立配置，再按 T13-02 原则追加。
- 全部五个键均无开发占位值（zsdev/pg 默认留空），`placeholderValue=null`，校验只要求非空；错误消息不回显任何密钥值。
