## 代码链路

| 图片来源 | 入口及存储路径 |
|---|---|
| 用户草图 | `前端程序/miniprogram/pages/ai-design/index.js`：`USER_SKETCH` 上传票据 → 预签名 PUT → complete；JPG/PNG ≤10MB |
| 用户头像 | `前端程序/miniprogram/utils/avatar-upload.js`：同一资产接口，≤2MB |
| 公司案例平面/立面 | `CompanyCaseImageService` → `AssetService.uploadCompanyImage` → 对象存储，JPG/PNG ≤20MB |
| AI 平面/立面 | `RuntimeAssetController` 签发输出票据 → `ai-runtime/src/runtime.mjs` PUT → `AiJobOrchestrationService` 校验 → `accepted/ai/`，≤20MB |
| 审核后的用户资产 | `AssetService` 复制净化后的图片到 `accepted/{assetId}/...`，避免上传票据覆盖已审核对象 |
| 图片读取 | 一次性下载票据 → 短期签名 GET；数据库保存 assetId/object key |

当前小程序只有一个用户草图选图入口，没有独立的「用户立面图上传」业务字段。本次统一其存储通道，不擅自新增设计流程或图纸类型；生成平面与立面都经过 AI_OUTPUT 链路。

开发环境取图原先固定调用后端内容端点并构造 base64，现改为按后端返回协议分流：HTTPS 在所有环境直接取 COS；local 仅在 dev 中重新领取一次性票据后读本地内容。短期签名不永久缓存，并发请求去重。不新增 SDK 或其他依赖。

## 服务身份权限

仅启用编程访问的 `zhongshu-cos-backend` 已创建并使用以下最小策略。`PutObject` 可以覆盖同名对象；后端资产 ID 与校验 token 负责对象命名隔离。永久密钥只放后端受保护的环境，不能放小程序、Runtime 或提交 Git。

```json
{
  "version": "2.0",
  "statement": [{
    "effect": "allow",
    "action": ["name/cos:PutObject", "name/cos:GetObject", "name/cos:HeadObject"],
    "resource": ["qcs::cos:ap-shanghai:uid/1397776231:zhongshu-design-assets-1397776231/*"]
  }]
}
```

资源表达式中的 uid 使用 APPID。权限依据：[腾讯云 API 授权策略](https://cloud.tencent.com/document/product/436/30580)。

## 回退与边界

代码可以通过 git revert 回退；云端桶和 CAM 配置是独立资源，Git 回退不会删除它们。首次切换前保留本地文件和数据库。切换后如产生 COS 新对象，回退到 local 前必须先按原 key 下载这些对象，避免仅改 provider 造成新图缺失。

数据库迁移另带 `migration-undo` 脚本。回退分辨率列前必须先停 Runtime 与任务提交，先停用 4K 规则，再回退应用和迁移；保留历史价格行与任务快照，不直接删除账务记录。云桶与本地测试账号、诊断对象不会因 Git 回退而删除。
