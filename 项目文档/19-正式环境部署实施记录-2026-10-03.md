## 三、踩坑实录（后续重装/排障必读）

1. **Flyway 权限**：底座 SQL 若以 postgres 超户导入，表归 postgres，应用账户 DELETE/DDL 全 42501。
   解法：`ALTER SCHEMA public OWNER TO zhongshu` + 逐表 `ALTER TABLE ... OWNER TO zhongshu`（REASSIGN OWNED 会撞系统对象报错）。
2. **Redis NOAUTH**：`prod` profile 才接 `spring.data.redis.password`；只挂 `pg` 时须补 `SPRING_DATA_REDIS_PASSWORD`。
3. **wxMpService appid不能设置为null**：ruoyi 底座公众号 SDK 只在 dev/local profile 配置；生产补 `WX_MP_APPID`/`WX_MP_SECRET`（占位即可，本业务不消费）。
4. **端口**：`pg` profile 默认听 **8080**，文档/约定是 48080 → `.env` 加 `SERVER_PORT=48080`。
5. **启动守卫**（RealServiceWiringPolicy）：`prod` profile 强制四端口全 real 且禁 stub；过渡期用 `--spring.profiles.active=pg` 单 profile（守卫按非生产放行 stub）。上 prod 前须：身份/支付/审核全 real + 五个 worker 开关 true + Actuator 基线（pg.yaml 已有部分，.env 已预置 worker 开关）。
6. **服务器访问 GitHub 超时**（acme.sh 装不上）→ 用 apt 的 certbot。
7. `install ... /dev/stdin` 不可靠，写 root:600 文件先落 /tmp 再 install。

## 六、本回合补充踩坑

- **PG 底座种子无 id 默认值（重大）**：ruoyi-vue-pro.sql 全部表 `id int8 NOT NULL` 裸定义、无序列默认值；项目 MP id-type=NONE"智能模式"在 PG 下解析为 **INPUT**——凡实体没挂 `@KeySequence` 的表（`system_login_log`、`infra_api_access_log`、`infra_api_error_log`…），MP 显式插入 NULL id 即 500。**登录 500"服务器错误"的真凶 = `system_login_log` 这张表**（同步写）。修复两层：①给 105 张非 identity bigint id 表建 `_id_seq` 序列 + 列默认值；②列默认值拦不住显式 NULL，再加 **107 个 BEFORE INSERT 触发器**（`public.set_null_id()`：NEW.id IS NULL 时取 `nextval(TG_ARGV[0])`）。已实测 admin 登录返回 accessToken。**若日后从种子重建库，此两步补丁必须重跑**（SQL 见本节与运维记录）。身份列（如 outbox_event）跳过。
- `build-release.js` 吃**环境变量**（ZS_RELEASE_API_BASE/ASSET_BASE/APPID）+ 位置参数出目录名（**不允许点号**，用 release-v1-2-1 这种）；`check-release.js <path>` 要传 `release/<name>` 相对路径。
- `upload-cos.js` 不要带 ZS_COS_ENDPOINT（带 scheme 会当主机名解析）。
- COS 私有桶静态图 403 → 桶策略按前缀最小化公开，别改整体公有读。
- COS 控制台策略弹窗：下拉选中后点弹窗内其他输入框收起，**别按 Esc（会整体取消）**。
