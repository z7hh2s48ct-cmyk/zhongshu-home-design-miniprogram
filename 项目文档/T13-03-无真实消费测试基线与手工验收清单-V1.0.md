# T13-03 无真实消费测试基线与手工验收清单 V1.0

日期：2026-09-09。所属批次：B0（基线与配置保护）。对应任务：T13 计划 §5 B0 表 T13-03。

验收标准（计划原文）：**建立无真实消费测试与手工验收清单｜HTTP 假服务器/SDK mock、隔离 PG 测试；真实检查默认不运行，明确账号、素材、金额及成本范围。**

本文是「如何在**不产生任何真实外部消费**的前提下自动化验证」与「**配置就绪后如何安全地进行真实验收**」的准备基线。本文**不是**真实渠道已接入或已验收通过的证明。

## 1. 目的与边界

- **目的**：为 B1（微信身份）、B2（腾讯云 COS）、B4（微信支付）的真实适配器预先建立可复用的隔离测试手段与门禁，使这些适配器在开发期即可被自动化测试覆盖，而**绝不触达真实微信/腾讯端点、绝不产生资金或计费**；同时把「真实验收」收敛为一条**默认关闭、需显式开启并注入受限凭据**的独立通道，并以本清单锁定其账号、素材、金额、成本范围。
- **边界（本文不声称）**：
  - 代码或隔离测试通过 ≠ 真实渠道可用；资料已填 ≠ 渠道已开通。
  - 本文不改动任何业务逻辑，不新增第三方依赖，不发明尚未被消费的密钥键（沿用 T13-02 原则）。
  - B3 内容审核本期后置，不在本清单准备范围。

## 2. 无真实消费测试基线（默认构建即运行）

三类隔离手段，均已在仓库落地并可复用：

| 手段 | 载体 | 用于 | 无真实消费的保证 |
|---|---|---|---|
| **隔离 PG** | Testcontainers `postgres:17-alpine`（一次性容器 + Flyway 迁移 + 用例间 `TRUNCATE`） | 各模块 `*ContractTest`（identity/design/commerce/ai/server 已用） | 一次性容器，测后销毁；不连生产/共享库；种子为合成数据 |
| **HTTP 假服务器** | `FakeHttpServer`（`yudao-spring-boot-starter-test` → `framework.test.core.util`，基于 JDK `com.sun.net.httpserver`，零新依赖） | B1 `code2session`、B4 微信支付 API 等**出站 HTTP** 适配器的协议解析与错误分支 | 绑定 `127.0.0.1` 临时端口；返回预置桩响应；请求被本地捕获供断言；不出本机 |
| **SDK mock** | Mockito（`mockito-inline`，随 `yudao-spring-boot-starter-test` 提供） | B2 COS（S3 SDK/`S3FileClient`）、B4 支付 SDK 等**SDK 型**适配器 | mock SDK 客户端接口，返回虚构结果；不发起真实 SDK 网络调用 |

补充基线（已有，非本文新增）：

- **Stub/Local 适配器**：`StubWechatIdentityAdapter`、`StubPaymentPortAdapter`、`LocalObjectStorageAdapter`、`StubContentModerationAdapter` 均为确定性、内存/临时目录实现，装配由 T13-01 的 `provider` 键驱动（`DevelopmentAdaptersContractTest` 覆盖）。
- **合成测试数据**：内存生成的 PNG/JPEG、固定测试用户 ID（如 101/202）、虚构 `appid`/`merchant`/`openid`；不使用任何真实用户数据。

> 约定：B1/B2/B4 新增真实适配器的**自动化测试一律走上述三类隔离手段**，测试代码中不得出现真实域名、真实凭据或真实订单号。真实端点只允许出现在下节门禁保护的「真实验收」通道中。

## 3. 真实检查门禁（默认不运行）

**双层门禁，防御纵深——任一层单独失效都不会触发真实外部消费：**

1. **构建层（标签排除）**：根 `后端程序/pom.xml` 的 `maven-surefire-plugin` 配置
   `<excludedGroups>${zs.test.excludedGroups}</excludedGroups>`，属性默认值 `real-acceptance`。
   凡标注 `@Tag("real-acceptance")` 的测试**不进入默认 `mvn test` 选择集**。
2. **用例层（凭据开关）**：真实验收用例须自带 `@EnabledIfEnvironmentVariable(named = "ZS_REAL_ACCEPTANCE", matches = "true")`；
   缺少该环境变量时整类禁用。B1/B2/B4 落地时应在此基础上再叠加各自凭据的 `assumeTrue`/`@EnabledIf...` 前置。

**开启方式（仅用于受控真实验收，不在 CI/日常本地构建使用）：**

```powershell
# 置空 excludedGroups（不排除任何组）+ 打开用例开关 + 注入受限凭据（示例）
$env:ZS_REAL_ACCEPTANCE = "true"
# $env:ZS_WX_APPID = "..."; $env:<B1/B2/B4 各自凭据> = "..."   # 由密钥托管注入，勿写入仓库/日志
.\mvnw.cmd -pl <模块> -am test "-Dtest=<真实验收用例>" "-Dzs.test.excludedGroups=" "-Dsurefire.failIfNoSpecifiedTests=false"
```

**门禁骨架**：`yudao-server/src/test/java/cn/iocoder/yudao/server/wiring/RealAcceptanceGateTest.java`
——B1/B2/B4 的真实验收用例以此为模板；在真实适配器就绪前，即使两层门禁都被打开，骨架也以 `Assumptions.abort(...)` 中止，**不发起任何真实调用**。

## 4. 手工验收清单（配置就绪后执行；明确账号/素材/金额/成本范围）

> 前置：对应批次真实适配器已开发且隔离测试通过；公司已按计划 §6 提供凭据并注入密钥托管；在**批准的测试范围**内执行，不操作无关客户数据。执行时逐项记录脱敏证据（请求 ID、测试订单号、截图、回读结果），但**不得**记录密钥、`session_key`、支付私钥、完整签名 URL。

### 4.1 B1 — 真实微信身份（`code2session`）

| 维度 | 范围 |
|---|---|
| **账号** | 2 个授权体验成员微信（计划 T13-09）；配套**独立测试激活码**，不复用任何生产激活码 |
| **素材** | 无（身份识别不涉及素材上传） |
| **金额** | 无资金流转 |
| **成本** | 无（微信登录接口免费；仅消耗体验成员登录次数，无计费） |
| **所需凭据** | 正式 AppID、AppSecret（密钥托管注入；`wechat-appid` 已被 `AppAuthController` 消费，AppSecret 由 B1 真实适配器落地时确定其环境变量名并纳入 T13-02 `REAL_MODE_REQUIREMENTS`） |

**验收点**：服务端 `code2session`（只接受客户端临时 `code`，不接受客户端自报 `openid`，`session_key` 不返回前端）；一码一账号；同一微信重登归属稳定；并发首登不重复建账号；不同微信不能抢占已兑换码；过期/撤销/已用码返回明确结果；已激活用户会话恢复可用；受限账号不能生成/充值。

### 4.2 B2 — 腾讯云 COS 私有存储

| 维度 | 范围 |
|---|---|
| **账号** | 腾讯云**受限子账号**凭据，权限仅限指定隔离测试前缀 |
| **素材** | 隔离测试目录下的**测试图片**（合成/样例），**非用户原图**；不迁移、不覆盖、不清空任何生产素材 |
| **金额** | 无直接资金流转 |
| **成本** | 产生 COS 存储 + 请求用量费，须限定在下方「测试用量上限」内；按腾讯云 COS 标准计费，**验收后 24 小时内清理测试前缀以停止计费** |
| **所需凭据** | 区域 region、私有 Bucket、endpoint、受限 SecretId/SecretKey（密钥托管；具体环境变量名由 B2 真实适配器落地时确定并纳入 `REAL_MODE_REQUIREMENTS`） |

**测试用量上限（建议值，执行前须书面确认；触及任一上限即停止）**：
- 对象数 ≤ 20 个；单对象 ≤ 2 MB；总存储 ≤ 40 MB。
- 请求数（含预签名 PUT、GET、HEAD 及必要重试）≤ 200 次。
- 隔离测试前缀留存时长 ≤ 24 小时；验收结束即删除全部测试对象并清空该前缀。
- 预估花费上限 ≤ ¥1（存储 + 请求用量，实际以腾讯云账单为准）；仅使用受限子账号，权限限定在该隔离前缀，不触达生产素材。

**验收点**：私有 PUT/GET/HEAD 与签名、region/bucket/endpoint 正确；预签名上传（小程序二进制 PUT，非 multipart）；存在性与大小校验；消毒回写；短期下载 URL；区分 404 / 权限拒绝 / 超时（不将所有错误当「不存在」）；上传完成后对象不可替换保护；**禁止公有读**、业务资产不用底座默认公开配置。

### 4.3 B4 — 微信支付与整单退款

| 维度 | 范围 |
|---|---|
| **账号** | 测试商户号 + 授权测试 `openid`（复用 B1 体验成员）；不涉及真实用户订单 |
| **素材** | 测试订单（虚构充值方案/商品）；不操作无关客户订单或余额 |
| **金额** | 批准的**最小测试金额**（建议 ¥0.01 起）；单笔与累计上限须**单独书面确认**；一次支付 + 一次**整单全额**退款 |
| **成本** | **真实资金流转**：支付 ¥X → 整单退款 ¥X，净额 ≈ 0；可能产生支付手续费（按商户费率，退款通常不退手续费）。严格限定在批准金额内 |
| **所需凭据** | 商户号、AppID 绑定/能力开通状态、商户私钥、商户证书序列号、APIv3 密钥、平台证书或支付公钥及其 ID、支付/退款回调 HTTPS 域名（私钥不进聊天/仓库/日志；环境变量名由 B4 真实适配器落地时确定并纳入 `REAL_MODE_REQUIREMENTS`） |

**验收点**：`openid` 取自已验证微信身份而非客户端；拒绝 AppID 不匹配；**去除 `STUB`/`stub-merchant` 硬编码**，真实渠道/商户写入交易事实；同订单稳定商户单号、金额/描述取订单快照；超时未知先查单、不重复建业务订单；授权用户才能领取本订单 `payParams`，客户端成功回调只触发查单不直接加点；通知 HTTP 入口以原始请求体验签解密、校验商户/AppID/币种/金额/订单归属、按渠道要求返回 HTTP 响应（不误用业务 `CommonResult`）、限请求大小；Inbox 先可靠接收再确认，重复/乱序只到账一次；账本只追加；整单退款事实驱动预留/冲正；退款 `PROCESSING/UNKNOWN` 不视为成功或失败，查单恢复幂等；金额异常/未知商户或订单/签名错误/缺实付金额不得误到账。

## 5. 本次执行记录（T13-03 隔离验证证据）

以下为本文配套代码在**无真实消费**下的自动化验证结果（JDK：Android Studio JBR；Maven：`mvnw` 3.9.16；Surefire 3.5.3）：

| 验证项 | 命令要点 | 结果 |
|---|---|---|
| HTTP 假服务器自测 | `-pl yudao-framework/yudao-spring-boot-starter-test -am test -Dtest=FakeHttpServerTest -Dsurefire.failIfNoSpecifiedTests=false` | `Tests run: 6, Failures: 0, Errors: 0, Skipped: 0`；BUILD SUCCESS |

**真实门禁 2×2 矩阵**（命令均为 `-pl yudao-server -am test -Dtest=RealAcceptanceGateTest -Dsurefire.failIfNoSpecifiedTests=false`——`-am` 会带上无此用例的上游模块，缺该开关上游会因「无匹配测试」先行失败（surefire 默认 `failIfNoSpecifiedTests=true`）；仅切换两层开关；每格运行前先删除上一格的 `RealAcceptanceGateTest` 报告文件以保证证据新鲜；四格均 BUILD SUCCESS，无一发起真实外部调用）：

| 运行 | 构建层 `zs.test.excludedGroups` | 用例层 `ZS_REAL_ACCEPTANCE` | surefire 观测证据 | 证明 |
|---|---|---|---|---|
| **A** 基线 | 默认 `real-acceptance` | 未设置 | `Tests run: 0`，无报告文件 | 两层同时阻断（默认态零执行） |
| **B** 双开 | 置空 `-Dzs.test.excludedGroups=` | `true` | `Tests run: 1, Skipped: 1`；`<skipped type="org.opentest4j.TestAbortedException">`（`Assumptions.abort`，`RealAcceptanceGateTest.java:32`） | 仅当两层都显式放行才选中并执行，且仍以 `abort` 中止——零真实调用 |
| **C** 仅开构建层 | 置空 `-Dzs.test.excludedGroups=` | 未设置 | `Tests run: 1, Skipped: 1`；`<skipped message="Environment variable [ZS_REAL_ACCEPTANCE] does not exist"/>`（**无** `TestAbortedException`，方法体未执行） | **隔离证明用例层**：构建层已放行，仍被 `@EnabledIfEnvironmentVariable` 在执行前禁用整类 |
| **D** 仅开用例层 | 默认 `real-acceptance` | `true` | `Tests run: 0`，无报告文件（类未选中） | **隔离证明构建层**：用例层条件已满足，仍被 surefire `excludedGroups` 标签排除 |

> 隔离性判读：B 与 C 的计数同为 `1 run / 1 skipped`，但**跳过原因不同**——B 是进入方法体后 `Assumptions.abort` 主动中止（`TestAbortedException`），C 是 JUnit 条件在方法执行前即禁用整类（`Environment variable ... does not exist`），二者差异即「用例层独立生效」的直接证据；D 相对 C 由 `1` 降为 `0`（类根本未选中）即「构建层独立生效」的直接证据。因此任一层单独失效，另一层仍足以阻断真实执行（防御纵深成立）。
