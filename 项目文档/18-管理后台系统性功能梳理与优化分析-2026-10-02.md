# 管理后台系统性功能梳理与优化分析

日期：2026-10-02
范围：管理后台全部 22 个业务页面 + 工作台 + 系统设置/运维支持入口
方法：逐页深读源码（含 11 页专项 UX 评审）+ 前后端能力交叉核实；与文档 17（信息架构重设计，六项决策已确认）合并成总路线图。
视角：运营人员日常使用——功能合并、布局、操作便捷性、业务合理性四个维度。

---

## 一、总体结论

1. **骨架健康**：22 页全部有真实后端支撑、无孤儿页面；核心资金/审核/预算操作有幂等键、双人复核、乐观锁、审计留痕——安全骨架在同类自建后台中属高水准。
2. **系统性短板集中在四类**：①同族页面交互不一致（时间格式四套、三态处理三档、确认弹窗强度三级、tag 两套）；②错误反馈吞没（4 处把后端具体错误吞成通用文案，其中 1 处完全静默，属资损误解级缺陷）；③状态机死状态（报价草稿、DISABLED 价格、PROCESSING 隐私申请无出口）；④"当前生效项不可见"（价格页多条 ACTIVE 并存无现价标识，审核历史轮次不可见）。
3. **运营效率 Top 瓶颈**（按影响排序）：审计页零筛选 → 预算明细逐行弹窗 → 报价草稿只增不减 → 项目预算只能精确查 ID → 价格停用静默失败。
4. **能力缺口**（非页面问题）：授权码无批次维度视图；运营无主动触达能力（小程序消息中心只收系统事件）；无内置角色模板；C端用户停用后端预留未开放（已确认开放）。

## 三、模块逐一分析（按文档 17 新分组）

### 3.1 户型与内容

**户型库管理**：问题与方案全部在文档 17 §R4（详情页、免下架编辑【已确认】、自定义风格、平面 1-8、操作栏隔离）。补充：新增保存后停留编辑页应有"返回列表"引导（create.vue:311）。

**AI案例审核**（review/index + detail）：
- F1(P1) 状态归属缺口：详情页状态含 RESUBMITTED/IN_REVIEW（detail.vue:135-136），列表 4 个 tab 无对应入口，重提件归属不明。
- F2(P1) 详情信息不足：不显示投稿用户、提交时间、公开展示/生成参考两项授权（列表有、详情无）——审核员判断能否发布的关键依据恰在详情页看不到；多轮审核无历史轮次区，上一轮退回原因不可见（detail.vue:13-27）。
- F3(P2) 「发布至户型库」无原因留痕（纯 confirm），与预算/报价发布的必填原因强度不一致（S3）。
- F4(P2) 批量按钮出现在表格下方滚动区，且批量确认不回显选中项授权状态，可能误放未授权内容（index.vue:107-122,182-190）。
- F5(P3) 两套近乎重复的表格模板（index.vue:26-68/70-105）；审核通过后发布需等页面刷新再点（detail.vue:111），高频两连操作被拆散。

### 3.2 用户与授权

**C端用户 / 授权码 / 人工调点单**：方案见文档 17 §R5 + 决策 1/3/6（解绑+发新码、订单 userId 筛选、开放停用）。
补充设计——**C端用户停用**（后端新端点 `PATCH /accounts/{id}` action=DISABLE，权限 `identity:account:manage` 种子随 010 补）：语义=撤销 ACTIVE grant + 拒绝新兑换/登录换取受限会话，点数余额冻结不清零（合规）；列表状态列已含 DISABLED 展示位。**授权码批次视图**：新增批次列表（批次号/数量/已兑换/交付方式/创建人/时间），点入按批次筛授权码——现列表已支持 batchId 筛选参数，只缺入口页（`GET /access-code-batches` 分页端点需后端补一个查询口）。

### 3.3 资金与点数

**充值管理（合并页）**：文档 17 §R3。补充：充值方案页无分页一次硬拉 50 条（plan:77），合并时补分页；订单页防重复提交守卫与两列状态分列是亮点，保持。

**设计点流水**：调点 tab 迁出后保持纯流水；9 类类型筛选完整。无新增问题。

### 3.4 预算与报价

**预算配置**（budget/index）：
- F6(P2) 用户覆盖价 tab 只能手输完整账号 ID（:551-554），无模糊搜索、无用户页跳转；运营处理覆盖价投诉时无干预入口（后端注释"本期不开放"，建议列入批次 F 待产品）。
- F7(P3) 0 元价的免费原因只在编辑弹窗可见（表格仅"免费" tag，:179）；目录 choices 初次加载失败后筛选不重拉且无提示（:625-628）；DISABLED 价格无"按此号新建"引导（S5 关联）。

**项目预算列表**（estimates）：
- F8(P1) 只能按完整 19 位项目编号精确查（:19,129-131），无用户/项目名模糊搜索——运营从用户反馈定位预算的第一步就卡住；"对外报价"需经详情两跳；"待补充"件无跟进动作引导。

**预算明细与修订**（budget/detail）：
- F9(P1) 补量逐行弹窗是最高频作业的最大瓶颈（:820-861），20 行预算=20 次弹窗往返；无行内编辑/批量补量/粘贴；保存区在页尾无吸底操作条（:247）。
- F10(P2) 排除标准项也须弹窗填原因，无快捷"排除"动作与批量排除（:403-409）；历史修订必须滚到底部点击查看（:279-284），无顶部版本切换；对外报价按钮 dirty 时静默消失无解释（:12）。
- F11(P3) 另存模板要求先保存/放弃修订（:947），顺序反直觉；修订对比不能任意两版互比（:289）；目录 fetchAll 无分页上限（:779-786，与 index 页 50 页上限不一致）。

**对外报价**（quote）：
- F12(P1) 草稿只增不减：stale 草稿不能发布/删除/作废（:376-378），废弃草稿永久堆积；一次报价输两次原因（创建:78-86 + 发布:217-224），应合并为一次。
- F13(P2) 撤回后业主端无报价展示，页面无醒目警示（仅 descriptions 一行小字 :36-37）；INCOMPLETE 卡创建时无跳转修订链接（:277-283）；预览行无高亮；版本表无分页保护。

### 3.5 价格管理

**出图计价**（generation-pricing）：
- F14(P2) 「调价」入口预填但弹窗标题恒为"新增生成价格"（:116），运营误以为覆盖旧价；无"当前生效价"标识（S6）。
- F15(P3) 停用为纯 confirm 无原因（S3）；张数上限 1-4 硬编码（:137-141），放开档位需改代码。

**业务积分价格**（usage-pricing）：
- F16(P1)**停用静默失败 bug**：retire 的 try 把 confirm 和 API 包在一起、catch 全静默（:192-204）——接口失败时运营以为已停用，价格实际仍生效，产生资损误解；无竞态保护（:140-159）；保存中弹窗可点遮罩误关（:84）。
- F17(P2) 无"调价"预填入口（对比兄弟页 :93），改价要手抄旧价；无现价标识（S6）；顶部指路文案无跳转链接（:20）。

### 3.6 运营与合规

**AI任务**：详情费用分项（提示词费/生图费/净消耗）按文档 17 §R6 + 决策实施；列表加净消耗列。其余结构健康。

**数据导出**（export）：
- F18(P2) "记录类型"是自由文本输入（:23-25），要求背业务枚举，形同虚设→改下拉（按类型联动候选）；create 失败吞后端原因（:169-171）。
- F19(P3) CSV 时间为 UTC、页面为北京（:102-104 footnote 有说明无切换）；审计页无"去导出"联动入口；无任务取消（需后端，列批次 F）。

**审计事件**（audit）：
- F20(P1)**全页零筛选**：无时间/类型/操作者/业务对象过滤，业务对象显示裸 `biz_type:biz_id` 不可点击（:21-50）——审计是留痕终点页，事件量增长后等于人工翻页取证。需补筛选四件套 + 事件详情展开（payload）+ biz 深链（跳审核详情/订单/调点单）。
- F21(P3) 页内无权限校验（S7）；event_type 与 action 两列语义重叠。

**隐私申请**（privacy）：
- F22(P2) 无状态/类型筛选、无自动轮询，待办淹没在历史里；EXPORT 行无核查能力（用户投诉"导出没收到"时无能为力）；关闭账号的"核对"（余额/订单/退款/任务）无核查清单入口。
- F23(P3) PROCESSING 疑似死状态（:75）；REJECTED 译"未完成"语义含糊（:77）。

### 3.7 工作台

快捷入口/待办 8 处跳转随 IA 同步（文档 17）；建议增补待办维度：授权码批次即将过期、待处理隐私申请、草稿报价积压（数据源现成）。
