## 依赖和制品

管理端锁定 axios 1.20.0、DOMPurify 3.4.15、设计器 3.5.0，锁文件中不再存在旧 wangEditor 引擎。设计器的 npm latest 标签并不代表 Vue 3 的兼容系列，因此没有盲目使用 latest。新的 Vite 构建报告 `dependency-reachability.json` 应同时满足 `legacyEditorModules=0`、`designerSource=true`、`safeEditorBridge=true`。

后端以实际打包 JAR 的扫描为依据，固定 Tomcat 10.1.59、Jackson BOM 2.21.5、Log4j BOM 2.25.5、PostgreSQL JDBC 42.7.12、HttpClient 5.6.3、HttpCore 5.4.3、Commons Compress 1.28.0 和 Bouncy Castle 1.84。Tomcat 公告指出 10.1.58 候选未通过发布投票，因此选用正式发布的 10.1.59，而不是仅照抄扫描器给出的最早修复版本。[Tomcat 官方公告](https://tomcat.apache.org/security-10.html)

`CVE-2026-7045` 对应 dynamic-datasource 表达式处理器。当前业务源码没有动态 `@DS` 使用；新增静态处理器替换库默认 Bean，拒绝以请求、Header、Session 或 SpEL 表达式决定数据源，并使用该库真实自动配置类验证替换生效。扫描结果仍保留这条公告，后续需跟踪上游补丁；不能将缓解措施写成漏洞库清零。

Runtime 使用 Node 24.19.0 / Alpine 3.24，更新发行版补丁，移除运行不需要的 npm/yarn，非 root、只读根目录和资源限制。初始 Debian 镜像的 122 条公告、初始 Alpine 的 10 条 OpenSSL 公告均保留扫描证据；更新后的制品重新扫描。[OpenSSL 3.5.8 发布说明](https://github.com/openssl/openssl/releases/tag/openssl-3.5.8)

小程序第三方子集更新并锁定为官方 `tdesign-miniprogram@1.16.1` 的 80 个文件，校验 npm tarball SHA-512；79 个文件与发布包一致，图标样式保留项目原有的离线字形映射，与现有全局字体配套。锁文件记录这一局部补丁的上游/实际 SHA-256，保留 MIT 许可证并随发布目录输出。内嵌 tslib 随该官方发布包追溯，未凭代码片段推定它的独立版本，也不宣称扫描器可以识别所有捆绑内部依赖。

`node scripts/supply-chain.mjs` 构建 Runtime、扫描管理端锁文件、后端 JAR、Runtime 镜像及小程序已知组件。扫描器固定版本及镜像摘要，输出 SBOM、后端制品摘要与汇总；高危或严重公告使流程失败。零组件也视作扫描覆盖失败。Trivy 0.74 的 fs 模式禁用了独立包分析，后端使用 rootfs 模式扫描嵌套 JAR。[Trivy 官方实现](https://github.com/aquasecurity/trivy/blob/v0.74.0/pkg/commands/artifact/run.go)

## 评审记录

这是实现者在开发后的代码复核和故障回归，不是独立人员批准。

1. 检查生成费用：缺失价格确认必须在扣点前拒绝；同一操作重试沿用原任务及冻结输入，更改需求应创建新操作。再次生成页面展示当前报价并保留原方案。
2. 检查完成与取消竞态：完成后不再接受新结果；校验/结算同任务行锁，迟到校验通过不能给终态追加计费槽位。首张图不再提前结束多图任务。
3. 检查字节完整性：读取/净化/审核在事务外执行，最终使用验证 token CAS。通过内容写入独立 accepted/ai 键；晋升读取实际摘要，拒绝旧隔离键。校验失败不能向公开展示或候选泄漏。
4. 检查外部边界：内部 API 对原始 JSON 字节签名，失效租约/旧 fencing/完成尝试、他人素材、撤回的生成授权均被拒绝。Runtime 只读取配置的存储 origin，不跟随重定向，不向存储地址发送供应商密钥。
5. 检查异常资源：图片和响应体先设上限；IMS 超时取消传输；每阶段调度故障隔离，日额度记录先于外部调用。Runtime 对未知付费结果不自动重试，避免把网络超时变为重复供应商扣费。
6. 检查供应链：发现并修复设计器预编译文件仍内嵌旧引擎、后端扫描零组件假通过、官方图标样式重新引入远程字体等问题；保留实际构建与失败后修复记录。

## 迁移、启用与回退

新增 Flyway `design/V20260913.214__moderation_recovery.sql` 和 `ai-orchestration/V20260913.403__runtime_completion_and_validation.sql`；不改已发布迁移。前者增加审核重试/全局日额度及 PENDING 审核证据，后者增加任务输入快照、完成屏障和结果校验租约。新增列与索引采用向前迁移。

正式启用前，先完成 RG3-人工配合清单，运行 pg,prod 完整装配；确认数据库迁移、私有存储、退款/导出/审核恢复与尾程调度全部开启，再启动 Runtime。`ai-runtime/README.md` 给出独立进程消费的实际环境变量。后端的旧 Provider 属性只是兼容绑定，不会自动将 Bean 或密钥传给 Runtime。

回退时先停止新生成准入和 Runtime 领取，保留任务、设计点、支付、审核证据及 Runtime 日志卷；由当前安全调度器处理在途任务。保留新增列，不删除或反向改写账务事实。不能回退到首图即结算、隔离区直接公开、缺价格确认或动态 SpEL 数据源路由的旧行为。优先向前修复；需要停业务时明确返回不可用，不能用 stub 伪造成功。

人工凭据、真实消费、云端策略、产品范围及独立 P0 审批统一放在同目录 `RG3-人工配合清单.md`，本轮未要求用户提前处理。

## 合并后补充复核

首次 RG3 合并后，主分支既有 Windows 文件仍含 CRLF，虽然 Git 对象按仓库规则为 LF，原始字节摘要检查出现误报。同组 worktree 快进到 main 后补充修正：文本只将 CRLF 规范化为 LF，不去掉空格、BOM 或其他内容，再校验锁定摘要。独立验证 LF、CRLF 均通过，追加内容仍被拒绝；小程序全套回归再次执行。业务代码与已通过全量/E2E 的代码保持一致，不为这一门禁修正重复执行无关的付费或后端测试。
