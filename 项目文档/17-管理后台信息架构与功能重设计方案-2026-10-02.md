## 二、现状核实关键发现（设计依据）

1. **品牌名只有 2 处 UI 硬编码/配置**：`管理后台/.env.local:2` 与 `.env.prod:1` 的 `VITE_APP_TITLE=众墅之家设计管理后台`（驱动浏览器标题、侧栏 Logo.vue、页脚），以及登录页 `src/views/Login/components/LoginForm.vue:5` 一处硬编码。logo 图片 `src/assets/imgs/zs-logo-white.png` 为纯图形（云形"众"标），不含文字。
2. **案例风格后端不设枚举**：`design_case_version.style_code VARCHAR(32)` 无 CHECK（V20260905.202 第 30 行），Controller 直接 `body.getOrDefault("styleCode", "MODERN")` 入库——自定义风格是纯前端改动。
3. **案例风格映射存在既有 bug**：create.vue 写死 `NEW_CHINESE/MODERN/EURO/AMERICAN`，而列表展示映射 `src/utils/zsFormat.ts:32-37` 只有 `NEW_CHINESE/MODERN/CHINESE/EUROPEAN`——`EURO/AMERICAN` 风格的案例在列表显示英文码。
4. **平面/层数后端无 1-4 上限**：DB 仅 `CHECK (floor_count >= 1)`；图片校验为 `1 <= floorNo <= floorCount`（CaseCatalogService:140-142），每层一张平面（唯一索引 case_version_id+role+floor_no）；"1-4"是前端自设（create.vue:43 max=4）。生成出图张数 1-4 是另一回事（生成侧），与案例平面数无关。
5. **案例详情/编辑现状**：列表行无点击交互、名称纯文本；预览是弹窗（descriptions+图纸网格，预览票据对草稿案例同样可用，无状态拦截）；编辑跳 `create.vue?id=` 已支持回填与改名，但**已上架案例必须先下架才能编辑**（create.vue:254）；新增保存后停留在编辑页不回列表。
6. **授权码现状**：无详情查看、无单个生成；两个假按钮——「导出授权码」（仅弹提示）与「启用」（仅弹"不可重新启用"警告）。码明文只在创建响应与"单码复制"（未使用码，留痕）两条路可取；已绑定码在领域模型中是 CONSUMED 终态**不可复活**，"解绑"（撤销授权 grants/revocations 端点已有）后码仍作废，用户重新激活只能发新码。
7. **账号详情无充值记录**：`GET /admin-api/design/v1/accounts/{id}` 返回 grants+recentLedger+stats，不含充值订单；admin 充值订单列表**无 userId 筛选参数**（RechargeOrderAdminController:35-95）。
8. **AI 任务费用**：详情已有 单位点数/扣点快照/结算退点/净消耗；**缺提示词费分项**——提示词扣点在 `service_usage_charge`（UNIQUE(product,biz_type,biz_id) → 每 job 恰一条 AI_PROMPT 记录，含 point_cost 单价快照），点数流水 `biz_type='ai_job'/biz_id=<jobId>` 可关联。前端从未展示该分项。
9. **价格页此前不可见的原因**：生成价格/业务积分价格两页是 2K/4K 计价与 AI_PROMPT 计费的唯一维护入口，但菜单过滤表漏键导致永不可见——**PR #5 已修复**。规则"只增不删"（调价=新增规则+停用旧规则），支持生效/失效时间。
10. **充值两页自包含**：plan/index.vue 与 order/index.vue 均为独立组件、无路由耦合，可直接嵌入 tabs 复用。
11. **人工调点单现状**：不是独立页，是设计点流水页的第二个 tab（含制单弹窗与双人复核），页面内还有两处制单入口。
12. **错误日志过滤能力**：`infra_api_error_log` 有 `applicationName`（本项目应用名）与 `requestUrl` 字段，查询参数支持 applicationName(eq)、requestUrl(like)；页面 queryParams 已有 requestUrl 字段但**无输入框**。
13. **上游菜单行**：CRM/商城/MES 等 1300+ yudao 模板菜单行存在于底座库，业务侧早已被 `projectNavigation.ts` 白名单裁剪；用户看到它们的唯一入口是「管理菜单」页（本方案将其隐藏后即不可见）。
14. **后端菜单种子已有分组**（9501 户型库/9504 用户与授权/9506 设计点与支付/9520 预算管理/9524 运营与审计），与 §三方案 B 的分组天然对齐；差异仅在个别归属与排序，可用一个 010 迁移对齐（低优先级）。

## 三、信息架构重组（R2+R3）

### 方案 B（推荐）：顶级分组化，22 项 → 7 组 13 项

去掉"业务管理"大杂烩，按职能分 7 组；每组 2-4 项；隐私申请自然落在最末组最后（满足"业务管理最下方"的意图：全菜单最后一项）。

```
工作台（首页，不变）
├─ 户型与内容            （原业务管理第 1 区块）
│   ├─ 户型库管理         ← 全菜单第一项（R2）+ R4 改造
│   └─ AI案例审核
├─ 用户与授权
│   ├─ C端用户
│   ├─ 授权码管理         ← R5：单次生成 + 详情抽屉 + 移除假按钮
│   └─ 人工调点单         ← 从设计点流水页拆出独立页（R3，用户指定放授权码之下）
├─ 资金与点数
│   ├─ 充值管理           ← R3：方案+订单合并页（订单 tab 默认，方案 tab 次之）
│   └─ 设计点流水         ← 纯流水（调点 tab 移出）
├─ 预算与报价
│   ├─ 预算配置
│   └─ 项目预算           （明细/报价为隐藏详情路由，不变）
├─ 价格管理
│   ├─ 出图计价           （原"生成价格"更名，含 2K/4K×阶段×张数规则）
│   └─ 业务积分价格       （预算测算/提示词调用计价）
└─ 运营与合规
    ├─ AI任务             ← R6：费用分项增强
    ├─ 数据导出
    ├─ 审计事件
    └─ 隐私申请           ← 全菜单最后一项（R2）
系统设置                 （R7：去掉管理员账号、菜单管理）
├─ 角色管理 / 操作日志 / 登录日志
运维支持
├─ 参数配置 / 文件管理 / 文件配置 / 接口访问日志 / 接口错误日志（R8 默认过滤）
```

合并明细：充值方案+充值订单 → 1 项；人工调点单独立成项但归属用户组；价格两页同组相邻（不合并页面，因两者权限码不同）。**净效果：顶层从 2 组 22 项 → 7 组 13 项**。

### 实现方式（低风险）

- **路由不动**：所有业务路由保持扁平注册（/zs/*），避免 vue-router 重复路径问题。
- `src/router/modules/zs.ts` 给每条路由 meta 加 `group: 'content' | 'auth' | 'fund' | 'budget' | 'pricing' | 'ops'`；`projectNavigation.ts` 的 `buildProjectMenus` 按 group 组装为多个顶级目录（图标+标题），权限过滤沿用 `businessPermissions`；`searchProjectMenus` 适配分组后数据源。
- 合并页：新建 `views/zs/recharge/index.vue`（tabs：充值订单=复用 order 组件、充值方案=复用 plan 组件），路由 `/zs/recharge`，原两路由标 hidden 保留兼容（老链接/收藏不失效）；工作台「支付未到账」待办跳 `/zs/recharge?tab=orders` 并定位。
- 人工调点单独立页：`views/zs/points/adjustments.vue`（现 ledger 页调点 tab 整体迁出），点数流水页删 tab 与两处制单入口；路由 `/zs/point-adjustments`。
- 工作台 8 处跳转路径同步（dashboard/index.vue:78-192）。
- 后端菜单种子对齐（可选，010 迁移）：调整 9506/9520/9524 组内归属与排序（价格移入"价格管理"、充值两行合一、人工调点挂 9504）——仅影响角色授权树的组织方式，不影响权限码，优先级低。

## 四、各需求设计

### R1 品牌名

- `.env.local` / `.env.prod`：`VITE_APP_TITLE=设计管理后台`（浏览器标题、侧栏、页脚自动跟随）。
- `LoginForm.vue:5` 硬编码同步改为「设计管理后台」。
- 图形 logo（云形"众"标）建议保留；若也要求更换，需设计提供新图（唯一资产 `zs-logo-white.png`/`zs-logo.png`）。

### R4 户型库管理四项

1. **详情页**：新增隐藏路由 `/zs/case/detail/:caseId`（`views/zs/case/detail.vue`）。列表「案例编号」「案例名称」两列渲染为可点击链接打开详情；详情页=现预览弹窗内容升级：参数 descriptions + 图纸分区大图（封面/立面/各层平面，沿用 preview-ticket 两段式加载，草稿可用）+ 状态时间线 + 操作区（编辑/上架/下架）。
2. **编辑与改名**：编辑入口保留 `create.vue?id=`（已支持 7 字段回填含名称）；详情页放「编辑」按钮。既有业务规则保持：**已上架案例须先下架再编辑**（防篡改已公开资产，见 §五-2 待确认）。
3. **自定义风格**：create.vue 风格控件改 `el-select allow-create filterable`，预置常用项（新中式/现代/欧式/美式/日式/法式…），输入即创建；后端 VARCHAR(32) 直接入库无需改动。同步修复 zsFormat.ts 映射 bug：映射表补 `EURO→欧式、AMERICAN→美式`，未映射值直接展示原文（自由风格天然兜底）。
4. **平面可增**：层数上限 1-4 → 1-8（create.vue:43），imageSlots 已随 floorCount 联动自动扩槽；编辑已有案例时可增大层数出现新槽位补传。上限 8 为展示安全值（后端无上限），超出再议。
5. **操作栏隔离**：行操作改为「编辑」（链接）＋「预览」（链接）＋「更多 ▾」（el-dropdown：上架/下架），统一 12px 间距与分隔线；上架/下架低频操作收进下拉，消除拥挤。

### R5 授权码管理改造

1. **单次创建**：页头「生成授权码」按钮 → 弹窗（有效期天数、用途备注）→ 复用批次接口 `POST /access-code-batches`（quantity=1、INLINE）→ 结果弹窗展示明文 + 一键复制。与「批量生成」并存（批量页保留）。
2. **详情抽屉**：列表新增「详情」操作（点掩码同效）→ 右侧抽屉四区块：
   - 基本信息：掩码、批次号、状态、有效期、用途、发放/暴露时间（全部现有列表字段聚合）；
   - 绑定账号卡：昵称/编号/授权状态/可用点数，点击跳 C端用户（数据复用 `GET /accounts/{id}`，已绑定码才显示）；
   - 该用户近期记录：点数流水（recentLedger 已有）+ 充值记录（依赖 §五-3 后端配合）；
   - 操作区：复制（未使用）、停用、删除（未兑换）、**解绑**（已绑定：撤销授权，界面文案明确"用户将立即失去访问，授权码不会恢复为未使用"）。
3. **移除两个假按钮**：「导出授权码」「启用」直接删除（启用违反"停用不可逆"安全规则，提示语已迁移到停用确认文案）。
4. **复制**：已有（copy 接口 + 权限），保留。
5. **重置语义（需产品确认，§五-1）**：推荐口径=「解绑 + 引导发新码」，不提供"码值重置"——已绑定码复活会破坏"一码一账号"审计链（兑换记录、授权记录均不可逆设计）。

### R6 API 花费透明

1. **价格可见性**（已解决一半）：出图计价（2K/4K×平面/立面×张数）与业务积分价格（BUDGET_ESTIMATE 每次、AI_PROMPT 每次）两个维护页已随 PR #5 回到菜单。
2. **单次任务花费分项**（后端小改 + 前端）：
   - 后端：`GET /ai-jobs/{jobId}` 管理端 VO 增加 `promptPointCost`（查 `service_usage_charge` where product='AI_PROMPT' and biz_type='ai_job' and biz_id=jobId 的 point_cost 与规则版本）；
   - 前端 AI任务详情弹窗费用区改为三行：`提示词调用（写提示词的文本模型）X 点`、`生图扣点（阶段×清晰度×张数）Y 点`、`结算退点 Z 点 / 净消耗 N 点`；列表增加「净消耗」列。
3. **规则可调整说明**：调价=新增规则（生效时间可设未来）+ 停用旧规则，界面已有；在两价格页顶部加"当前生效规则"汇总卡（阶段×清晰度现价、AI_PROMPT 现价），运营无需从规则列表推算。

### R7 系统设置精简

- `projectNavigation.ts` supportPaths 删除 `/system/user`（管理员账号）与 `/system/menu`（管理菜单）→ 系统设置只剩：角色管理、操作日志、登录日志。
- **CRM/商城等上游模块**：业务侧早已被白名单裁剪；其唯一可见入口「管理菜单」页隐藏后彻底不可见。上游菜单行与角色-菜单外键**保留在库中不删**（维持底座升级能力，删除会造成 yudao 上游同步冲突且无收益）——符合 T11"展示精简、不删底座"既定口径。
- 角色管理保留（R7 不涉及；且刚落地的业务权限种子必须经角色管理授予）。角色页授权树中上游节点是否折叠/隐藏为可选项（§五-4）。

### R8 错误日志项目过滤

- `views/infra/apiErrorLog/index.vue`：① queryParams.applicationName 默认值设为本项目应用名（与后端 `spring.application.name` 一致，实施时从 `application.yaml` 取值写入前端常量）；② 补 requestUrl 筛选输入框（queryParams 字段已存在，仅缺 UI）。
- 「接口访问日志」页同处理（applicationName 默认值 + 保留现有筛选），保持一致。
- 非项目日志数据**不删除**（框架底座共用），仅默认视图过滤；用户可清空筛选查看全部（排障兜底）。

## 五、决策点（2026-10-02 运营方已全部拍板）

1. **授权码"重置"语义**：✅ 按推荐 A 执行——解绑（撤销授权，用户立即失去访问）+ 引导发新码；不提供"码值复活"。
2. **已上架案例编辑**：✅ 免下架直接编辑。已核实后端 `updateCase` 仅乐观锁校验、无上架状态拦截（CaseAdminController.java:131-145），仅需移除 create.vue:254 的前端门禁；已上架内容将即时生效（新版本），编辑页保留提示文案。
3. **充值记录打通**：✅ admin 充值订单列表加 `userId` 筛选参数（授权码抽屉与 C端用户抽屉共用）。
4. **角色授权树**：✅ 隐藏上游 CRM/商城等非本项目节点（角色页菜单树按 /zs 业务节点过滤）。
5. **数据导出**：✅ 扩充类型——新增「授权码批次交付记录」「C端用户清单」。
6. **C端用户停用**：✅ 开放（后端 AccountAdminController 从只读补停用端点，见文档 18 §停用设计）。
