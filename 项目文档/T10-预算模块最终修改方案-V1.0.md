# T10 预算模块最终修改方案 V1.0

> 日期：2026-09-08  
> 定位：预算专项的新需求与实施设计正本；尚未实现，不代表功能已验收。  
> 源码核对基线：`d3ae7b4`。任务与验收见 [T10 工作清单](T10-预算模块任务清单与验收标准-V1.0.md)，动态状态只更新 [项目状态看板](项目状态看板.md)。

## 1. 需求来源与适用顺序

1. 当前会话最新补充：管理员能新增尚未预设的预算项，使其参与整体预算。
2. 会话“0908 | 分析设计预算业务逻辑”（2026-09-08）中用户确认的简化方案：地区单价 × 计价数量；设计项目参数导入；后台地区定价；管理员调整最终对外报价。
3. 同一会话后续视觉决定：占地面积不与面宽、进深重复展示；主体类 3 项、外装类 7 项；业主侧不展示内部计价过程。以本目录 `预算模块效果图/小程序-v2/` 的 7 张图为标准页面基准。
4. 用户提供的 `2026预算公式培训上线.xlsx`：作为基础选项、单价与计价单位的来源，不覆盖以上产品范围与简化决策。

计价文件当前位于仓库外的工作区根目录，SHA-256 为 `6443A1D492459BBE785AB288EBF51E65EE20465469D2629416DCF801625FE636`。Sheet1!A1:C50 有计价文字，Sheet2/Sheet3 为空；本文件不将它描述为已运行的 Excel 计算模型。原件未改动、未自动复制到仓库。实现时整理受控选项映射和来源单元格，不把内部价表打包进小程序。

本方案取代旧版“两页区间预算”、旧“九项明细”口径及早期复杂高度附加建议。历史审计保留为现状证据，不覆盖受控后端合同；实现前按 T10-01 更新受影响的合同及版本登记。

## 2. 最终目标与范围

完整链路为：选择设计项目、导入基础参数、选择预算配置、生成分项参考预算、保存预算；管理员可补充自定义项、核定价格和数量、形成新预算版本，再调整并发布对外报价。

### 2.1 标准分类与扩展

| 分类 | 固定标准预算项 | 自定义扩展位置 |
|---|---|---|
| 主体类 | 地基基础、主体结构、屋面结构 | 主体类明细中的“补充预算项” |
| 外装类 | 装饰构件、门窗、外墙漆、文化石、灯具、防水防雷、保险 | 外装类明细中的“补充预算项” |

- 门、窗分别计价，对外合并到“门窗”；防水、防雷分别计价，对外合并到“防水防雷”。父级金额只汇总子行，不能再与子行重复相加。
- 10 个标准项保留稳定编码，不因改名、排序或新增自定义项改变身份。
- 自定义项也必须属于上述一个分类；本期不新增第三大类，不允许删除标准分类。
- 栏杆不作为第 11 个固定标准项自动计入；确有需求时，管理员可通过本次新增的自定义项能力添加。
- 新增“下拉选项”与新增“预算项”是两种操作。例如“门窗”下增加规格是选项；增加“排水沟施工”是一个独立预算项。

### 2.2 本期包含与不包含

包含：小程序 7 页及状态、设计参数快照、后台地区/预算项/选项/单价配置、项目临时补项、分项计算、预算保存与查询、报价调整与发布、历史版本、安全与测试。

不包含：高度阶梯/超高附加规则、自由代码公式、完整工程量清单软件、合同签署、支付结算、PDF/Excel 导出、新增独立无设计项目的预算业务。入口缺少设计项目时引导选择已有项目，不虚构项目或强制先执行 AI 生成。

## 3. 自定义预算项的落地规则

这部分是对用户最新补充的实施设计：采用“可复用模板 + 当前项目临时项”，不引入公式编辑器。

### 3.1 两种使用方式

| 方式 | 管理员操作 | 作用范围 | 对小程序的影响 |
|---|---|---|---|
| 可复用预算项 | 在预算项管理中新增名称、分类、计价方式，配置选项和地区价格 | 管理员可用于多个项目 | 默认仅管理员添加；明确启用“用户可选”且价格配置完整后，在配置页补充区出现 |
| 项目临时项 | 在某项目预算详情中点击“新增预算项”，填名称、分类、单位、数量、单价 | 仅当前项目的新预算版本 | 不进入其他项目的下拉列表；发布后在该项目分类明细中展示名称和金额 |

临时项可显式“另存为模板”；不会自动污染公共目录，也不会把项目专用价格自动发布成地区通用价。新增模板不会追溯加入已有预算。

### 3.2 必须保存的内容

| 字段 | 规则 |
|---|---|
| 稳定 ID/编码、名称、分类 | 名称必填；同名不得被系统自动合并；模板编码唯一 |
| 来源 | 标准项、公共自定义模板或项目临时项；记录模板版本或创建人 |
| 单位与计价数量来源 | 占地面积、建筑面积、屋顶面积、已知长度/周长、个数、套数或管理员录入 |
| 地区与单价 | 模板采用地区价格版本；临时项采用项目专用单价并保存原因 |
| 数量、单价、行金额 | 草稿可缺数量/价格；计价时由服务端算行金额，不信任客户端总额 |
| 生效状态 | 待补充、已计价、明确排除；模板另有草稿/启用/停用状态 |
| 对外名称、说明与内部备注 | 字段分离；所有已计入的有效费用均有对外名称和金额，内部备注不下发 |
| 操作记录 | 增改删原因、操作者、时间、旧值与新版本 |

### 3.3 未明确价格如何处理

- 不知道价格时允许先保存待补价草稿；`null` 不等于 0 元。
- 后台补齐单价、计价数量后参与本分类及系统总额；固定费用使用“元/项 × 1 项”。
- 赠送项可以明确设置 0 元，但需标记“免费”并填写原因；不允许以默认 0 代替缺价。
- 负数费用不作为自定义项录入；优惠/加价通过报价调整处理。
- 缺价、缺量的已选项显示“待补价/待补量”，仅展示“已计价小计”，不得冒充完整总预算；未补齐或未明确排除前禁止发布最终报价。
- 管理员可明确排除一项，但必须保存理由和范围；对外显示未包含项目的名称，不显示内部理由。取消选中与缺失计价数据必须区分。

## 4. 输入、工程量与地区价格

### 4.1 用户输入保持简洁

基础参数页保留占地面积、层数、屋顶面积、建造地区。项目名称与方案版本真实导入；“恢复导入值”恢复该次导入快照，不悄悄读取后来改变的项目数据。

服务端保存的面积字段相互独立：

- 优先采用设计项目已经保存的占地面积、建筑面积、屋顶面积。
- 无已存占地面积时，仅在面宽、进深齐全且有效时计算占地面积。
- 无已存建筑面积时，可用占地面积 × 层数形成推导值，并记录来源；有项目实际建筑面积时不覆盖它。
- 屋顶面积直接来自项目或用户输入，不擅自等同于占地面积。
- 修改占地面积/层数时，仅重算标记为推导来源的建筑面积；既有独立建筑面积与新参数不一致时提示复核并标为待确认，不静默覆盖。
- 每个字段保存 `PROJECT`、`DERIVED`、`USER_OVERRIDE` 或 `ADMIN_OVERRIDE` 来源及原值。参数修改只影响新测算，不修改已经保存的预算。

### 4.2 不把完整工程量清单塞给小程序用户

灯具长度/个数、门数量、文化石周长、防水面积等优先从项目结构化数据读取。缺失时交由管理员在预算详情补量，不要求小程序新增一串专业输入，也不从单一占地面积猜测周长。

允许有据可查的标准数量转换，例如价表中的窗面积 = 建筑面积 × 0.25；转换必须有字段、单位、来源和版本，不能在金额计算阶段重复乘一次系数。具体转换由 T10-01 形成白名单映射；未定义的外墙系数或工程量不设置猜测默认值，可由管理员核定数量或配置有依据的数量参数后使用。

“屋顶面积”与 Excel 的“顶楼建筑面积”等用词在映射表中分别登记：按已确认简化业务使用屋顶面积作为屋面计价输入，不擅自换算斜屋面展开面积。涉及复合方案时列出实际参与的计价子行。

### 4.3 地区价格

- 同一选项可以在不同地区有不同价格，计价单位必须匹配数量单位。
- 默认要求匹配所选地区的有效价格；本期不做隐式跨地区兜底，缺价提示并交由后台补齐。
- 新价格版本采用草稿、校验、发布、生效/停用流程；已生效版本不可原地改写。
- 同地区同选项生效区间不能重叠，时间统一存储、展示时明确时区。
- Excel 价格作为待核对的初始配置，不自动认定为所有地区的正式价格；发布生产价格必须是授权管理员的显式操作。

## 5. 统一计算与对账

所有金额由服务端计算：

```text
计价子行金额 = 地区或项目专用单价 × 计价数量
预算项金额 = 该预算项下所有计价子行金额之和
主体类小计 = 主体类已计价标准项 + 主体类已计价自定义项
外装类小计 = 外装类已计价标准项 + 外装类已计价自定义项
系统测算总额 = 主体类小计 + 外装类小计（仅在预算完整时成立）
对外最终报价 = 系统测算总额 + 报价调整金额
```

工程实现规则：金额以整数分保存；单价最多 2 位小数、数量最多 4 位小数，使用十进制定点运算；逐计价子行按 `HALF_UP` 舍入到分，再加总，不先汇总未舍入小数。个/套/户等不可分单位要求整数，面积/长度可为小数。超精度输入明确拒绝，不悄悄截断。范围和总额上限在 T10-01 固定并测试，防止溢出。

总额和分项按元核对。小程序首页可显示万元并四舍五入，但不得拿万元显示值反算报价；明细提供精确到分的金额查看方式，用于解释显示精度导致的表面差额。

### 5.1 系统测算与人工报价分开保存

- 管理员输入最终报价，后端计算差额；也可输入调整差额，后端计算最终报价。同一请求只接受一种编辑方式，拒绝互相冲突的值。
- 最终报价不得为负；调整原因必填，保留报价前值、操作者、时间和版本。
- 自定义费用属于预算明细，不当作报价差额；优惠/协商加价属于报价调整，不伪装成预算项。两者不重复计费。
- 分类小计始终展示该预算版本的真实计算结果，不为了凑最终报价而按比例改写分项。
- 对外报价存在差额时增加简洁“报价调整”金额行，使分类合计 + 调整 = 最终报价；不暴露内部成本、单价、计算公式或内部调整理由。

## 6. 保存、版本与发布

| 对象/操作 | 行为 |
|---|---|
| 生成参考预算 | 产生可用 ID 读取的不可变测算快照；完整性为 `COMPLETE` 或 `INCOMPLETE` |
| 保存预算单 | 幂等地将该快照加入项目已保存预算列表；重复点击不重复测算、不重复收藏 |
| 用户调整参数/选择 | 新建测算快照，不覆盖之前保存的快照 |
| 管理员补项、补量、改单价 | 从选定预算派生工作草稿；每次保存生成新修订，旧版保留 |
| 报价草稿 | 绑定一个完整、明确的预算修订 ID，保存独立调整与最终金额；不向业主公开 |
| 报价发布 | 校验归属、完整性、版本和权限后发布不可变报价；新修订使旧草稿需重新复核 |
| 再次调整已发布报价 | 新建报价版本；旧发布版本只读，不能覆盖 |

默认发布到该项目预算入口，不自动发送微信消息。预算历史通过项目内列表进入，复用结果页，不额外要求第 8 张独立一级页面。旧预算链接读取原快照；项目最新已发布报价采用单独引用。失效/撤回显示状态并保留历史，不把新结果覆盖到旧 ID。

公共模板启用、草稿修改或管理员保存临时项本身，不代表已经向业主发布。对外可读取的发布版本包含全部计入的自定义费用及其所属分类，不能藏起一笔已计入总价的收费。

### 7.2 管理后台

增加预算管理菜单，复用当前 Vue 管理端表格、表单、弹窗和权限体系：

| 页面 | 功能 |
|---|---|
| 地区管理 | 地区编码、名称、启停、排序 |

| 对外报价 | 完整预算复核、最终报价/差额、原因、对外预览、发布与版本记录 |

报价预览必须使用与小程序相同的对外数据合同。无权限用户不能通过隐藏按钮之外的直接 API 调用更改价格、追加费用或发布报价。

### 7.3 后端模型与接口边界

以下为逻辑模型，表名和路由在 T10-01/02 固化，不能视为已经存在的接口：

- 地区、预算项目录、选项/方案及其子行、地区价格版本。
- 结构化项目预算参数及来源快照、预算主记录、不可变预算修订、预算明细子行、用户保存关系。
- 报价修订、发布引用和审计事件。模板、项目临时项采用明确来源类型，共用分项汇总逻辑。
- 历史记录引用的模板、价格和子项不能物理删除；停用只影响新选择。

小程序接口：读取项目预算参数、读取地区可用选项、创建测算、按 ID 获取公开预算详情、保存/列表、读取自己项目的已发布报价。

管理端接口：地区/模板/选项维护、价格版本校验发布、查询预算内部详情、补项补量生成修订、另存模板、创建/调整/发布报价、读取审计历史。

安全与一致性要求：

- 沿用当前已激活且未受限用户准入；校验项目属于当前用户、方案版本属于该项目。管理端同时校验业务权限和数据范围。
- 所有跨端 ID 使用字符串，不把 Snowflake ID 转为 JavaScript Number。
- 小程序请求只允许参数和选项，不接受单价、行金额、报价差额；后台请求必须有相应权限，服务端重新计算。
- `App` 与 `Admin` 使用分离 DTO/字段白名单；小程序 JSON、网络响应、日志和缓存均不能泄露内部单价、系数、公式、内部备注。
- 同一逻辑操作的幂等键重复请求返回同一结果；同键不同请求体拒绝。预算修订/发布使用预期版本进行并发控制，冲突提示刷新。
- 明细、合计、版本、发布和审计写入事务化，失败全部回滚，避免明细已存但总额未更新。

## 8. 旧数据与兼容

旧区间预算保留为 `LEGACY_RANGE` 只读记录，继续显示原上下限及旧提示；不凭空拆成 10 项，也不默认取中值生成新总价。新预算使用 `ITEMIZED_V1` 标识，前后端分支明确。

使用新增迁移和渐进切换，不改写已经发布的 Flyway 文件。先部署兼容后端与管理配置，再切换小程序；无正式价格时不启用对外新计价。回滚应能停止新建但保留新版本只读数据，不通过删除历史报价实现回滚。

旧 E2E 当前有 `ruleVersion === 'VAR1'` 的错误假设；`VAR1` 是地区标记而非价格版本 ID。T10-17 更新新旧合同断言，不能为迁就旧断言修改业务版本语义。
