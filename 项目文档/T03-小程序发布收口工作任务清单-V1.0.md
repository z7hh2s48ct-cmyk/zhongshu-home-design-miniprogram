# T03 小程序发布收口工作任务清单 V1.0

> 编制日期：2026-09-08  
> 对应基线：`main` / `dc0f41145752fce1bba24cfdfe3648a2a2f91c92`

## 1. 总体完成标准

以下条件全部满足后，T03 才能关闭：

- 使用真实小程序 AppID；开发版、体验版、正式版分别指向受控环境，正式版不存在 localhost、游客 AppID 或演示激活旁路。
- 认证、token 刷新、授权失效、弱网和并发请求行为可预测，不把 403 错误误判成登录失效。
- “我的方案、我的投稿、收藏户型、充值记录、设置”均为真实页面和真实数据，不再调用统一占位提示。
- 参考图片完成产品合同、上传安全、对象存储、审核、授权和 AI Runtime 传递闭环。
- 微信开发者工具的实际编译包体满足平台当前限制；建议把主包控制在 1.5 MiB 内并保留增长余量。
- Node 测试、开发者工具运行时自动化、测试环境 API E2E、视觉回归和真机矩阵均有可复跑脚本或签字证据。
- 体验版验收单记录版本号、代码 SHA、AppID、环境、后端版本、数据库迁移版本、测试结果和已知限制。

退出条件：代码扫描不再发现 localhost；抓包可识别客户端版本且无秘密信息。

## 4. 工作包 B：激活门禁、登录与会话

### MP-AUTH-01 隔离并移除正式版演示激活旁路（P0，前端，0.5～1 人日）

- [ ] 把 `DEMO-ONLY` 从业务代码移到只允许 `develop` 的测试适配器。
- [ ] `trial`、`release` 构建中即使后端不可用也必须失败关闭，不允许本地写入激活态放行。
- [ ] 正式包启动断言演示适配器未被打包或不可执行。
- [ ] 清理曾由演示码写入的本地授权快照，避免升级后继续沿用。

退出条件：正式环境输入 `DEMO-ONLY` 只能得到普通兑换失败，不能进入任何受限页面。

### MP-AUTH-02 建立明确的授权状态机（P0，前端，1 人日）

- [ ] 用 `UNKNOWN / CHECKING / ACTIVE / RESTRICTED / EXPIRED / OFFLINE` 替代单一布尔缓存。
- [ ] 激活成功必须以服务端兑换结果或服务端 grant 快照为准；不能先本地设为 true 再异步纠正。
- [ ] 冷启动、回前台、支付返回、授权撤销和网络恢复时定义刷新策略与缓存 TTL。
- [ ] 网络失败时隐藏敏感业务内容并展示可重试状态；后端继续作为最终授权边界。

退出条件：授权撤销、过期、弱网、存储失败和回前台均有自动化用例，无受限内容闪现。

### MP-AUTH-03 接入 refresh token（P0，前端，1～1.5 人日）

- [ ] 在 `api.js` 增加 `/auth/token-refresh`；当前后端接口已经存在。
- [ ] access token 失效时以 single-flight 方式只刷新一次，并重放原请求一次。
- [ ] 并发请求共用同一个刷新 Promise；刷新失败统一清会话，避免请求风暴和循环刷新。
- [ ] 区分 401 与 403：401 处理会话；403 保留会话并按权限/授权状态提示，不能直接清 token。
- [ ] 退出登录时同时清除 access token、refresh token、授权快照和业务临时状态。

退出条件：覆盖刷新成功、刷新失败、并发刷新、重放失败、403、退出登录六类用例。

### MP-AUTH-04 登录与隐私同意顺序（P0，前端/后端/产品，0.5～1 人日）

- [ ] 冻结首次登录、隐私同意、授权码兑换的顺序和可返回规则。
- [ ] 未同意必要隐私项时，不向 AI Provider 或对象存储发送用户素材。
- [ ] 隐私版本变化后重新征得同意，并保留后端证据。

退出条件：新用户、老版本用户、撤回同意用户均有明确可执行流程。

## 10. 推荐排期与并行关系

### 第 0 阶段：决策与外部申请

先完成 P-01～P-06，并立即申请 E-01～E-08。AppID、域名、COS、支付和 AI Provider 是日历关键路径。

### 第 1 阶段：工程安全基线

并行执行：

- 线路 A：MP-ENV-01～04。
- 线路 B：MP-AUTH-01～04。
- 线路 C：MP-PKG-01，开始清理未引用资源。
- 线路 D：MP-QA-01/02 搭测试框架。

完成后才允许产生体验版候选。

### 第 2 阶段：页面功能闭环

MP-ME-01～05 可由 2 名小程序开发并行；MP-ME-06 最后统一收口。后端仅需补 `allowedActions` 和发现的字段合同问题。

### 第 3 阶段：上传与资源闭环

MP-REF-01 完成后，MP-REF-02 与 MP-REF-03 并行；随后执行 MP-REF-04。MP-PKG-02/03 可与该阶段共用 COS 和域名工作。

### 第 4 阶段：验收

依次执行 MP-QA-03～06、MP-REL-01～03。真实支付和真实 AI 尚未完成时，最多只能给出 `TRIAL-GO`，不能给出 `RELEASE-GO`。
