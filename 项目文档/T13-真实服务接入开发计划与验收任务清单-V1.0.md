## 1. 最新需求与范围

用户已纠正：**不需要手机号，直接使用激活码登录。** 因此取消手机号登录、短信验证码、腾讯短信配置、手机号绑定/找回、手机号账号合并等全部新增任务，不新增短信依赖。

用户再次明确“不需要手机号”，歧义已解除：本期不接腾讯短信，不新增手机号字段、短信验证码、手机号账号或相关页面。

按当前已有实现理解，用户界面保持“输入激活码→登录并激活”；后台仍通过 wx.login 临时 code 识别微信身份，激活码绑定该账号。保留这一内部步骤是为了复用现有一码一账号规则、跨次登录的记录归属及微信支付身份，不增加独立微信登录按钮、不索取手机号。若业务希望激活码本身成为可跨微信重复使用的账号密码，则属于不同账号模型，需要另行明确，本文不擅自改变现有绑定规则。

本期范围：真实微信身份识别、激活码入口完善、微信支付及整单退款、腾讯云 COS 私有存储、环境配置与这些链路的三端验收。用户已确认内容审核以后接腾讯云，本期不实施、不要求购买审核套餐。费用调研见 [腾讯云图片审核费用调研](./T13-腾讯云图片审核费用调研-2026-09-09.md)。

AI 生图供应商和 Runtime 同为后续独立接入批次。本期为其准备真实存储能力，不凭“等内容”擅自选定模型、购买服务或提交用户图纸给未确认供应商。

审核后置边界：保留现有审核端口、状态及发布授权检查，不删除或关闭门禁。COS 先做隔离测试目录的真实存取验证；开发 Stub 的通过记录不能作为公开发布条件。生产在缺少真实审核实现时仍保持安全失败；若希望审核接入前先对外开放上传/发布，必须另行批准并实现可追溯的人工审核流程，不在本期默认放行。

## 3. 开发原则与状态定义

1. 最小改动：优先在现有端口后增加真实实现，保留本地隔离测试能力；不重写预算、案例或账本。
2. SDK 选择：优先复用现有且适配的依赖。支付签名/验签/解密优先成熟 SDK，不为少一个依赖自行重写金融协议；若需新增，记录原因和锁定版本。
3. 每批先补测试再实施，验证失败时不静默退回 Stub、不默认放行审核、不伪造支付成功。
4. 不直接改用户余额、不覆盖历史支付事实、不自动迁移或清空现有业务数据。
5. 不自动合并微信账号；unionid 或激活码均不能成为客户端自报身份的依据。
6. 密钥只进后端密钥托管或本地忽略文件；不进前端、日志、截图、文档。测试使用虚构凭据与隔离服务。
7. 真实发短信已取消；真实交易、退款、云上传和审核验收使用明确的测试账号/订单/素材/额度范围，不操作无关客户数据。

状态统一为：待开发→开发中→代码及隔离测试通过→配置就绪→真实联调通过→验收完成。资料已填不等于渠道可用；某批代码通过不等于整期完成。
