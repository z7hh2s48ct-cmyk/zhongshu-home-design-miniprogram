# T14 激活用户当地单价覆盖 任务清单与验收标准 V1.0

> 日期：2026-09-14  
> 上游：[T14 方案](T14-激活用户当地单价覆盖方案-V1.0.md)。本文件定义工作与验收，不代表测试已执行；动态状态统一登记 [项目状态看板](项目状态看板.md)。

## 1. 工作包定位与开工条件

T14 是在 T10/T13 之外追加的预算增强专项：激活用户按账号永久覆盖预算单价，以匹配当地成本；平台默认价固定为武汉基准价，不再做地区价格配置。

- 顺序原则：先合同与数据迁移，再后端取价层与接口，随后两端界面，最后自动化与 E2E 验收；各任务实现时同步写对应测试，不将测试留到末尾。
- 集成与迁移验收需要可用 PostgreSQL/Redis 与 Docker（JDK 17），与 T10/T13 既有环境要求一致；纯合同、服务层单测可先行。
- 分支沿用 `task/T14-xx-short-name`，只包含该任务相关变更；不改历史签署合同，按仓库流程登记新版本。
- 红线：任何任务不得给用户侧开放 `budget_item_price` 写通道，不得改动已保存预算/报价的快照语义；发现冲突即停并回溯本方案。

## 3. 逐任务工作定义

### T14-01 固化合同

- 工作：按方案第 4～6 节固化 `budget_account_price` 字段与约束；三个 App 接口出入参、错误码 `BUDGET_ACCOUNT_PRICE_INVALID`、限流阈值；`pricing_snapshot` 新增 `priceSource`/`accountPriceId`/`accountPriceVersion` 字段语义；权限矩阵（用户三接口=非受限会话；管理端查询=`design:budget:query`）；目录 `AVAILABLE` 判定新规则的合同描述。
- 输出：受控接口与字段合同登记；测试 fixture 规范（覆盖生效/恢复默认/基准缺价补价/非法输入样本）。
- 验收：合同无未定义字段；AC-01、AC-07 所涉错误码与语义全部登记。

### T14-02 数据模型与迁移

- 工作：编写 `V20260914.215__t14_account_price.sql`（DDL 见方案第 4 节）；部分唯一索引与普通索引；确认与既有 Flyway 编号无冲突。
- 验收：空库与 T13 基线库上迁移/回滚通过；重复执行幂等；AC-08 前置（唯一索引存在）。

### T14-03 账号价服务与取价覆盖层

- 工作：`budget` 包新增账号价服务：`resolve(accountId, optionId)`、`upsert`、`reset`、`listByAccount`；`ItemizedBudgetService.createSnapshot` 在基准价查询后叠加覆盖价（方案 3.1 两层规则），快照写入 `priceSource` 等；`BudgetCatalogService` 增加账号感知目录变体（覆盖价或基准价任一存在即 `AVAILABLE`）；CUSTOM_TEMPLATE 项不参与覆盖。
- 约束：不改 `budget_item_price` 任何写路径；不动 LEGACY_RANGE；基准价 `priceVersion` 在覆盖场景仍照旧入快照。
- 验收：AC-02、AC-04、AC-05、AC-06、AC-09 的服务层单测通过。

### T14-04 App 接口

- 工作：新控制器 `AppAccountPriceController`（GET/PUT/DELETE `/design/v1/budget/my-prices*`），统一 `requireUnrestricted` 门禁；入参校验（正整数分、≤1 亿分、reason ≤500、选项合法）；`@RateLimiter`；恢复默认幂等。
- 验收：AC-01、AC-03、AC-07、AC-08 通过；受限会话与无效 token 行为与既有预算端点一致。

### T14-05 小程序"我的当地单价"

- 工作：新页 `pages/budget/prices`：逐项展示基准价/我的单价/价格来源与更新时间，行内编辑（元输入，2 位小数，提交转分）、恢复默认、空态与缺价说明；入口挂在预算参数页与 body/exterior 配置页（"已启用我的当地单价"提示）；接 `utils/api.js` 新端点；金额展示规则与既有预算页一致。
- 约束：不在前端计算或缓存总额；未激活用户不可达（沿用 `utils/access.js` 门禁）。
- 验收：AC-02、AC-04、AC-07、AC-09 的界面路径可用；小程序既有用例回归通过。

### T14-06 管理后台收窄与只读查询

- 工作：预算目录页文案改"基准价格"，停用新增地区入口（保留数据与既有行管理）；实现覆盖只读查询页/面板（按账号查，`design:budget:query`），只读无干预按钮。
- 验收：AC-10、AC-11 通过；管理端既有用例与类型检查/Lint/构建通过。

### T14-07 后端自动化矩阵

- 工作：单测覆盖两层取价、upsert 幂等、并发唯一索引、校验边界；集成测试覆盖迁移、门禁 403、快照字段、缺价补价、恢复默认；改价前后已保存预算逐分比对。
- 验收：AC-01～AC-09 全部有自动化断言；`node scripts/verify.mjs backend` 通过。

### T14-08 前端行为测试

- 工作：小程序（prices 页交互、门禁、错误提示）与管理端（文案收窄、只读查询）行为测试；接入根级统一验证与 CI 既有拆分，不新增工作流。
- 验收：`node scripts/verify.mjs mini` 与 `admin` 通过；AC-07、AC-09 前端断言落地。

### T14-09 三端 E2E 与收口

- 工作：e2e 套件新增检查点：激活用户设置覆盖价 → 新测算采用覆盖价并标 `ACCOUNT_OVERRIDE` → 恢复默认 → 新测算回基准价；未激活访问 403；基准缺价 + 覆盖补价可用；改价不影响已保存预算与已发布报价；管理端基准价发布流程回归；旧 54 检查点全量回归。微信开发者工具逐页视觉核对 prices 页与入口。
- 验收：AC-12 通过；看板登记证据与遗留项（真机、生产价格配置等不得提前记通过）。

## 4. 验收标准（AC）

| ID | 标准 |
|---|---|
| AC-01 | 受限（未激活）会话调用 my-prices 三接口返回 403，错误语义与既有预算端点一致 |
| AC-02 | 设置覆盖价后发起新测算，该选项行单价 = 覆盖价、行金额 = 覆盖价 × 数量（服务端计算） |
| AC-03 | 用户覆盖操作全程对 `budget_item_price` 零写入；其他账号测算结果不受影响 |
| AC-04 | 恢复默认后新测算回基准价，快照 `priceSource=DEFAULT`；重复恢复幂等 |
| AC-05 | 改价（设置与恢复）前后，已保存预算、历史版本、已发布报价的金额与快照逐分一致，无漂移 |
| AC-06 | 覆盖生效时快照含 `priceSource=ACCOUNT_OVERRIDE`、`accountPriceId`、`accountPriceVersion`，且基准 `priceVersion` 照旧记录 |
| AC-07 | 非法输入全部拒绝：0、负数、>100 万元、>2 位小数、非数字、未知/禁用选项、CUSTOM_TEMPLATE 项、reason 超长 |
| AC-08 | 并发 upsert 不产生双条 ACTIVE（唯一索引兜底）；同价重复提交结果一致 |
| AC-09 | 基准缺价 + 有覆盖 → 目录 `AVAILABLE` 且可测算；基准缺价 + 无覆盖 → 维持 `MISSING_PRICE`；基准有价 → 目录与测算行为与现状一致 |
| AC-10 | 管理端草稿→发布/停用基准价流程回归通过；地区维度不再出现在新增配置入口 |
| AC-11 | 管理端覆盖查询只读且要求 `design:budget:query`；越权 403 |
| AC-12 | E2E 新增检查点全绿且旧 54 检查点全量回归；`node scripts/verify.mjs all` 通过 |

验收人安排遵循仓库惯例：P0 实现者不得为唯一验收人；真实生产价格核定与生产发布不在本专项内。
