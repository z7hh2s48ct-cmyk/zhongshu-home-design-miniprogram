## 一、环境准备

### 1.1 必装软件

| 软件 | 版本要求 | 检查命令 | 安装方式 |
|---|---|---|---|
| JDK | 17.x | `java -version` | `brew install openjdk@17` |
| Maven | 3.8+ | `mvn -version` | `brew install maven` |
| PostgreSQL | 17（16 可） | `psql --version` | `brew install postgresql@17` 或 Docker |
| Redis | 6.x+ | `redis-cli ping` | `brew install redis` 或 Docker |
| 微信开发者工具 | 最新稳定版 | — | [下载地址](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html) |

**Docker 快速启动数据库（推荐）**：

```bash
docker run -d --name zs-pg \
  -e POSTGRES_DB=zhongshu_design \
  -e POSTGRES_USER=zhongshu \
  -e POSTGRES_PASSWORD=zhongshu_dev \
  -p 5432:5432 \
  postgres:17-alpine

docker run -d --name zs-redis \
  -p 6379:6379 \
  redis:7-alpine
```

### 1.2 JAVA_HOME 设置

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
export PATH=$JAVA_HOME/bin:$PATH
```

## 二、后端部署步骤

### 步骤 1：创建数据库

```bash
psql -U postgres -c "CREATE DATABASE zhongshu_design OWNER zhongshu;"
psql -U postgres -c "ALTER USER zhongshu PASSWORD 'zhongshu_dev';"
```

### 步骤 2：设置环境变量

```bash
export ZS_PG_URL='jdbc:postgresql://127.0.0.1:5432/zhongshu_design'
export ZS_PG_USERNAME='zhongshu'
export ZS_PG_PASSWORD='zhongshu_dev'
```

### 步骤 3：编译并启动

```bash
cd /Users/honor.pei/Documents/ruoyi/ruoyi-vue-pro
mvn install -DskipTests
mvn spring-boot:run -pl yudao-server \
  -Dspring-boot.run.profiles=local,pg \
  -Dspring-boot.run.jvmArguments="-Xmx512m"
```

> 首次启动 Flyway 自动执行全部迁移建表。种子数据（计价规则/充值方案/示例案例/测试授权码）自动写入。测试授权码明文在控制台搜索 `测试授权码`。

### 步骤 4：验证

```bash
curl http://localhost:48080/actuator/health
psql -U zhongshu -d zhongshu_design -c "\dt"
curl -s http://localhost:48080/app-api/design/v1/recharge-plans | python3 -m json.tool
```

## 五、本项目自有密钥

| 配置键 | 要求 | 开发默认值（pg profile） | 生产获取 |
|---|---|---|---|
| `zhongshu.identity.access-code-pepper` | ≥32 字符 | 硬编码 dev 值 | 密钥托管 |
| `zhongshu.identity.access-code-pepper-version` | 固定 `v1` | `v1` | — |
| `zhongshu.identity.access-code-artifact-key` | Base64(32B) | 硬编码 dev 值 | 密钥托管 |
| `zhongshu.identity.wechat-appid` | A1 的值 | `stub-appid` | 微信后台 |

> 生产通过环境变量 `ZS_ACCESS_CODE_PEPPER` 等注入，缺失时兑换/发码接口快速失败。

## 六、效果图上 COS 步骤

**结论：上传 COS，不留在包内。** 现状 `assets/v12/` = 6.1MB > 微信主包上限 2MB。

| 类别 | 处理 |
|---|---|
| 界面骨架（logo/图标 <500KB） | 留在包内 |
| 案例效果图（约 18 张） | **上传 COS 私有桶** → COMPANY 案例资产 → 页面 src 改为接口 URL |

### 步骤

1. 获取 COS 凭据（上表 #8~#10）→ 配置到后端
2. 实现 `ObjectStoragePort` COS 版适配器（端口和测试已就位）
3. 管理端批量上传效果图 → 关联案例版本
4. 前端 `src="/assets/v12/xxx.png"` → `src="{{item.coverUrl}}"`（接口返回）
5. 删除 `assets/v12/` → 主包 <1MB
6. downloadFile 合法域名加 COS 域名

### 过渡方案

`LocalObjectStorageAdapter` + `AppAssetContentController`（票据换内容端点）已可用。前端按「src=接口 URL」写好，切 COS 时前端零改动。

## 七、常见问题

| 问题 | 原因 | 解决 |
|---|---|---|
| `relation "recharge_plan" does not exist` | Flyway 未跑 | 确认 profile 含 `pg` |
| `缺少 pepper` | 密钥未配 | 设 `ZS_ACCESS_CODE_PEPPER` |
| 前端请求全失败 | 后端未启动 | 启动后端 + 勾"不校验域名" |
| 页面显示空数据 | 种子未写入 | 检查 `seed-dev-data=true` + `[DevDataSeeder]` 日志 |
| 管理后台无法登录 | 底座 PG 化未完成 | 平台阶段 1A/1B 事项 |
