## 二、问题清单与处理意见

### P1 — 开箱即断，上线前必须修

**1. zsdev 默认授权码制品密钥不是 32 字节，管理端创建授权码直接 500**
- 现象：管理后台创建授权码批次报 500；后端日志 `java.lang.IllegalStateException: access-code-artifact-key 必须是 32 字节`。
- 根因：`application-zsdev.yaml:46` 的默认值 `ZGV2LW9ubHktYXJ0aWZhY3Qta2V5LTMyLWJ5dGVzISEh` 解码后是 **33 字节**（"dev-only-artifact-key-32-bytes!!!"），通不过 `AccessCodeCipher.artifactKey()` 自己的校验。
- 临时处置：已在本地 `后端程序/.env` 注入随机 32 字节 Base64 密钥（gitignored，不入库）。
- 处理意见：修正 yaml 默认值为合法 32 字节，或启动时对该默认值做 fail-fast 校验并给出可复制的修复提示。**一行修复，建议立即提交。**

**2. 本地启动脚本的引擎模式没跟上 COS 资产通道切换，所有 AI 生成任务必败**
- 现象：生成任务在引擎侧报 `STORAGE_ORIGIN`，任务 FAILED（小程序端表现为生成失败但按规则自动退点，用户体验是"永远生成不出来"）。
- 根因：`c9caf498` 把后端资产通道切到 COS（签发 `https://<bucket>.cos...` 地址），而 `后端程序/script/dev/start-local-bg.ps1` 仍让引擎跑 `ZS_AI_STORAGE_MODE=local-fs`（只认 `local://` 地址）。
- 处置：已把脚本修正为 `https` 模式 + 桶 origin 白名单（本次测试即用此配置真跑成功）；`.env` 追加 `ZS_ACCESS_CODE_ARTIFACT_KEY`。
- 处理意见：脚本修正已落地，随本次报告一并提交；团队内同步"引擎模式必须与后端 provider 配对"。

**3. 预算地区/价格目录开箱为空，小程序预算流程第一步即断**
- 现象：`budget_region` 表 0 行，小程序"建造地区"下拉为空、生成按钮永久禁用（文案"基础参数有误"），真实运营环境无从下手。
- 根因：预算目录完全依赖管理端手工配置（10 标准项 + 35 选项 + 13 项价格），无种子数据、无配置引导页。
- 处置：本次已通过管理端 API 完成全套配置（地区 ZSDEV1 + 10 项 + 35 选项 + 13 价格发布），随后预算链路全通。
- 处理意见：①管理后台增加"预算地区/价格目录"配置入口的引导或校验提示（后台当前缺该配置页，与文档 14 的遗留结论一致）；②提供一套可一键导入的开发种子（地区+黄金价）；③小程序端把"暂无地区"从表单错误升级为引导性空态。

### P2 — 一致性/健壮性

**4. 首页概览接口的授权状态与真值不一致**
- `GET /app-api/design/v1/home` 对已激活会话仍返回 `accessGrantStatus: ANONYMOUS`（`/access-grant` 实测 ACTIVE， grantedAt 为当次）。前端首页快照因此长期显示 ANONYMOUS。当前门控未依赖该字段（受保护端点自行拦截），但任何信任此字段的逻辑都会误判。处理意见：home 端点按当前会话解析授权状态，或明确该字段语义并让前端不再消费。

**5. 自定义导航栏胶囊尺寸调用未防护，每个页面加载必抛异常**
- 每页 console 固定出现 `getMenuButtonBoundingClientRect:fail global.windowMap is not iterable` + `TypeError: Cannot read properties of undefined (reading 'height')`（v12-navbar）。模拟器/自动化环境必现，真机低版本或极端时机同样可能踩中。处理意见：调用处 try-catch + 默认导航高度兜底（微信官方推荐模式）。

### P3 — UX 细节（对标顶尖小程序）

**6. 激活页说明卡第一条图标显示为数字"1"**：`pages/auth/index.wxml` 中 `<view class="note-icon">1</view>` 应为图标（第二三条分别用了 user-filled/service 图标）。风格不统一，属明显瑕疵。

**7. 授权码输入 placeholder 示例与真实格式不符**：placeholder 写 `ZSZJ-XXXX-XXXX`，真实码为 `ZS-XXXXX-XXXXX-XXXXX-XXXXX-XXXXX-X`（6 段、段长不一）。用户照示例输入会反复失败。建议改为真实格式截略展示（如 `ZS-XXXXX-…-X`）。

**8. budget/history 直达入口显示错误文案**：无项目上下文直接进入显示"项目编号无效，请从预算配置页重新进入"的 error 态。建议改为空态+引导按钮（"去创建 AI 方案"/"从我的方案选择"），与全站空态风格一致。

**9. 模拟支付通道下 UI 与扣款时序错位**：开发者工具中 `wx.requestPayment` 弹窗被自动取消（走 fail/cancel 分支，页面停留钱包页），但后端 mock 通道已自动扣款到账——用户视角"没付成功钱却扣了"。建议：mock/stub 通道不返回 `payParams`（让流程走查单页），或 fail 分支先调一次订单状态查询再决定提示文案。

**10. 生成任务首次发起前的确认弹窗未展示即被自动化吞掉（记录用）**：`wx.showModal` 确认弹窗内容实测为"出图 X 点；提示词模型调用 Y 点"，文案清晰；真人路径无问题，仅自动化测试需 mock（测试资产已内置）。

### 测试环境稳定性坑（写进规程，非产品缺陷）

- **IDE 服务端口设置会被运行中的 IDE 回写关闭**：`enableServicePort:false` + 旧端口会覆盖磁盘配置，CLI 全部失效。规程：冷启动前先杀干净 IDE 进程→改配置→再 `cli auto`（`artifacts/ui-test` 可沉淀为一键脚本）。
- **长自动化会话后模拟器渲染器会冻结**：画面停在旧帧、`miniProgram.screenshot()` 返回 0 字节，但应用逻辑仍在运行（自动化操作、导航、任务全部正常）。规程：截图批量任务前重启 IDE；截图优先用 `screenshot()` 返回值自写盘。
- `start-local.ps1`/`.env` 的 UTF-8 无 BOM 文件被 PowerShell 5.1 按 GBK 解析，中文注释尾字节会吞掉下一行换行符（本次 `ZS_COS_ENDPOINT` 因此静默丢失，已修脚本加 `-Encoding UTF8`）。任何读 UTF-8 配置的 PowerShell 脚本都要显式声明编码。

### 新发现的问题 ❌

**P1-A：小数面积的 AI 投稿无法上架，且无"核定面积"入口（UGC 死胡同）**
- 现象：AI 生成项目天然产生小数面积（12.6×13.8×2=347.76㎡），投稿审核 APPROVE 后发布被拒：`1071000002 案例目录暂仅支持整数平方米，请先核定投稿版本面积`。
- 根因：`SubmissionReviewService.publishApprovedAsCase` 用 `intValueExact()` 强校验（注释明示"不能静默截断小数或填假值"，方向正确），但**全系统没有任何"核定面积"入口**——管理端案例编辑仅限 COMPANY 案例，投稿人也无法修改已冻结版本的面积。审核通过后卡死，用户视角"已通过却永远上不了架"。
- 处理意见：管理端审核/发布页提供"面积核定"动作（取整+留痕+通知投稿人），或案例目录面积字段支持一位小数。**推荐前者**（保持目录整数口径）。

**P1-B：立面出图方向与输入平面方向不一致时生成必败（默认组合即坏）**
- 现象：平面竖版（默认）+ 立面横版（默认）→ 立面任务 `PROVIDER_IMAGE_SIZE_MISMATCH` 必败；同一项目立面改竖版（与输入一致）后立即成功。
- 根因：供应商出图方向**跟随输入参考图**（竖版平面 → 竖版立面输出），引擎却按任务 `imageOptions` 的期望尺寸强校验。产品默认值恰好构成必败组合；只有用户把平面和立面选成同向才能成功（首轮 4K 测试通过正是同向的偶然）。
- 处理意见：三选一——①立面任务创建时将期望方向对齐输入平面方向；②引擎校验失败后自动按输入方向重试一次；③立面设置页锁定与平面一致的方向并说明原因。推荐 ①+③。

**P2-C：预算草稿绑定 access token 摘要，token 静默刷新即全丢**
- 现象：地区/屋顶面积设置成功后（会话未退出），再次进入预算页回到"待选择"；逐项配置 10 类目的长表单存在中途全丢风险。
- 根因：`budget-draft.js` 草稿键 = `zs_budget_draft_v2:<access token 摘要>:<projectId>:<versionId>`，access token 按设计会刷新轮换，摘要随之变化导致旧草稿永远读不到。
- 处理意见：草稿作用域改绑稳定标识（账号 ID 或会话代际 epoch），而不是短期 access token。

**P3-D：AI 案例上架标题为"AI 案例 · 投稿 <ID 串>"**，无可读作品名；发布页也没有作品名输入。建议投稿表单增加"作品名称"（可选，缺省用风格+面积生成）。

**P3-E（观察）**：下架案例的详情接口返回 403"没有该操作权限"，前端显示"案例加载失败"。安全语义合理，体验上可接受；如需更好可区分"已下架"态。

### 结论

UGC 域（投稿→审核→发布→图库→通知）与授权码管理域功能完备、防御到位；**上线前必须处理 P1-A（否则部分真实投稿必然卡死）与 P1-B（否则默认方向组合的立面生成必败）**。预算完整测算链路可用，草稿丢失问题（P2-C）建议随下个迭代修复。

### 本轮新发现

**❌ P2-D（资损级）：任务取消在"领取前"永不收敛，点数滞留不退**
- 现象：QUEUED 任务点"取消生成"后 `CANCEL_REQUESTED` 挂 5 分钟+（引擎健康、空闲），状态不收敛为 CANCELLED，已扣的 10/30 点出图费不退（ledger 只有扣款无退款）。两个任务均复现。
- 根因：`AiJobOrchestrationService.completeCancellation(jobId)` **只有单元测试调用**，生产代码无任何调度路径触发它；而 claim 只领可运行任务，CANCEL_REQUESTED 的 QUEUED 任务永远不会被领取 → 完成取消的代码成为死代码。注释表明设计意图是"settle(CANCEL) 统一处理退款"（修复 C1 资损缺陷），但只修了领取后取消，领取前取消无人收敛。
- 修复建议：在 claim 轮询或独立调度中扫描 `status='CANCEL_REQUESTED' AND runtime_completed_at IS NULL` 的任务调用 completeCancellation；或 claim SQL 允许领取 CANCEL_REQUESTED 任务后立即走取消结算。

**观察（非缺陷）**：cancel 的余额在请求时刻即冻结（保留语义），UI 提示"退点自动到账"在当前缺陷下不会兑现，修复 P2-D 后自洽。
