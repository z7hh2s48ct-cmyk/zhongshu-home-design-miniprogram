## 1. 全局约束（每个任务都隐含，不再逐条重复）

**技术栈固定项**

- JDK 17 + RuoYi-Vue-Pro JDK 17 维护线 + Spring Boot；固定上游精确 SHA 后迁入。
- 数据访问 MyBatis / MyBatis-Plus；所有 SQL 必须在真实 PostgreSQL 上验证，禁止 H2/SQLite 冒充。
- PostgreSQL 17 优先（16 可接受），唯一业务真相源；Redis 只做会话/限流/短缓存/锁，不保存余额、订单或任务终态。
- 迁移工具推荐 Flyway；每个迁移有逆向脚本或明确 restore-before-change 方案。
- 对象存储腾讯云 COS 私有桶；数据库保存 object key，不保存长期签名 URL。
- 事件用 PostgreSQL Outbox + dispatcher；P0 不引入 Kafka/RabbitMQ/Nacos/Dubbo/Seata。
- Flowable 只承载审核人/待办/流转；领域表才是正式状态真源。

**API 合同固定项**（架构 §7.1）

- 三个分面前缀：小程序 `/app-api/design/v1`、后台 `/admin-api/design/v1`、Runtime `/internal-api/design/v1`。
- 统一 `CommonResult<T>` / `PageResult<T>`，JSON `camelCase`，时间 ISO 8601 UTC；不自创第二套响应壳。
- POST 创建任务/订单/投稿必须支持 `Idempotency-Key`；同主体同 Key 同请求体返回原结果，Hash 不同返回 `IDEMPOTENCY_KEY_REUSED`。
- 小程序列表用游标分页，后台列表用页码分页；后台编辑返回 `version`/ETag。
- 业务对象返回 `allowedActions`；客户端不自行推导权限。
- 稳定错误码按架构 §7.6 的 22 个码，不新增同义码。
- 幂等键按架构 §11.1 表格执行。

**四条不可拆事务边界**（蓝图 §6，任何任务不得违反）

| 事务 | 必须同一 PostgreSQL 事务提交 | 明确排除 |
|---|---|---|
| 兑换授权码 | 锁码、兑换事实、AccessGrant、码已消费、审计 Outbox | code2session 外部调用 |
| 创建 AI 任务 | 计价快照、锁账户、扣点流水、charge、job、Outbox | Provider 调用 |
| AI 终态结算 | 正式候选、终态、settlement、差额/全额退点流水、余额、Outbox | Provider 调用、COS/格式/内容安全/质量校验 |
| 充值到账 | 唯一 rechargeCredit、基础/赠送流水、余额、fulfillment、Outbox | 支付通知验签、渠道退款 |

外部调用一律在事务外，以 Inbox/Outbox、幂等键和状态 CAS 衔接；禁止打开数据库事务后等待微信、COS 或 Provider。

**每个任务统一的收尾流程**（蓝图 §9，7 步顺序执行）

1. 格式化、lint、类型检查、架构/静态规则；
2. 受影响单元 + PostgreSQL 集成和合同测试，里程碑包跑全量；
3. 依赖漏洞与 changed-files 密钥扫描；
4. 完整 diff 自审（死代码、调试输出、错误处理、外部超时、日志敏感字段、迁移可逆性）；
5. 启动应用与最小页面/API smoke；
6. 中文 Lore 提交，写明 `Tested`、`Not-tested`、风险和回滚；迁移先独立提交；
7. 更新状态账本与证据，不因"代码存在"跨越证据等级。

**证据等级**：`CODE_PRESENT → AUTOMATED_VERIFIED → STAGING_VERIFIED → REAL_CHAIN_VERIFIED → PRODUCTION_GO`。Stub 阶段最多 `AUTOMATED_VERIFIED`；真实链路包完成后最多 `STAGING_VERIFIED`，须真实受控闭环才可标 `REAL_CHAIN_VERIFIED`。

T00(G0A)
  └─ P1A → P1B → P1C
        ├─ P2A ────────────────┐
        ├─ P3A → P3B ──────────┼─→ P5 → P6 ─┬─→ P7A ─┐

                          P8A → P8B → P8C ───────────┤

- **可并行点**：P1C 之后 P2A/P3A/P4A 三线并行；P6 之后 P7A/P7B 并行。

## 11. 回归必测：关键故障注入矩阵（蓝图 §8）

每条竖切收尾时按此矩阵回归，全部通过才算包退出：

| 故障点 | 通过标准 |
|---|---|
| 授权码锁定后进程退出 | 整体回滚；重试可成功且只消费一次 |
| 扣点后、job 提交前退出 | 扣点与 job 均不存在，或重试返回同一完整事务结果 |
| Runtime 旧租约回写 | 被 fencing 拒绝，不改变结果/终态 |
| 结果写入中重复回调 | Inbox 幂等重放；每槽位最多一条 ACCEPTED，拒绝不占死槽位 |
| Runtime 返回非法 object key/Hash 或损坏文件 | 只停留隔离区标 REJECTED，不建候选、不参与结算 |
| 取消与结果同时到达 | 同锁递增 decisionSeq，按 receivedSeq < cancelSeq 裁决；终态 CAS 后不可改 |
| 结果已齐、结算提交前退出 | 重试后只产生一个 settlement，退款不超扣款 |
| 请求 N 却返回 N+1 | 只接受/计费 N 个；多余结果留诊断 |
| 支付通知 Inbox 落库后退出 | 渠道可安全重发；后台最终处理且不重复到账 |
| 支付通知永久丢失 | 主动查单恢复支付事实和到账 |
| credit 写入中退出 | credit、两条流水、余额、fulfillment 同进同退 |
| 重复渠道退款/冲正 | 累计受上限约束，原账不可删除 |
| 退款前已有任一扣点 | 返回 REFUND_POINTS_ALREADY_USED，不建退款单、不形成负余额 |
| 退款预留后渠道失败/未知/成功 | 失败释放、未知保持并查单、成功转冲正；各路径幂等恢复 |
| 授权撤回与新任务并发 | 新任务同事务校验失败；已接受任务有授权版本快照 |
| 批量审核/导出半失败 | 每项结果可见、可重试；成功项不重复执行 |
