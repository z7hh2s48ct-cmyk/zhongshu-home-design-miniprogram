# P1C：可靠事件、审计与异步交付基线（冻结记录）

> 冻结日期：2026-09-05
> 归属：底座 Infra 扩展（架构 §6「底座 Infra 扩展（非新业务模块）」），代码位于 `yudao-module-infra` 的 `cn.iocoder.yudao.module.infra.zhongshu.*` 包

## 1. 端口与实现

| 端口 | 实现 | 职责 |
|---|---|---|
| `ReliableEventPort` | `JdbcReliableEventPort` | 业务事务内追加 `outbox_event`；与业务写同一线程绑定事务，回滚同回滚 |
| `AuditPort` | `JdbcAuditPort` | 落 `audit_event`；审计明细禁止敏感明文 |
| `DeliveryPort` | `JdbcDeliveryPort` | `export_job`（异步导出，CAS 推进状态）、`one_time_delivery_ticket` / `one_time_download_ticket`（一次性票据） |
| `OutboxDispatcherService` + `OutboxEventSink` | — | dispatcher 租约领取（FOR UPDATE SKIP LOCKED + 事件级 claim 租约）与 at-least-once 投递 |

使用规则：

- 业务模块依赖 `yudao-module-infra`（允许依赖，P1A 架构测试只禁四个业务模块互依），只经端口访问，禁止直接读写这些表。
- `append` 必须在业务事务内调用；`dispatchOnce` 的 Sink 投递在事务外，消费方必须幂等。
- 平台工程表（outbox/audit/export/ticket/dispatcher_lease）使用 `GENERATED BY DEFAULT AS IDENTITY` 主键，是对 P1B「业务表雪花 ID」约定的工程表例外（文档化差异）。
- dispatcher 实例登记在 `dispatcher_lease`（心跳/可观测）；事件级抢占由 `outbox_event.claimed_by/claim_expires_at` 承担，崩溃实例租约到期即可被重领。
- Sink 失败退避重试（`retry_count`，退避由调用方传入），≥5 次进入 `DEAD` 人工处置；无 Sink 支持的事件按失败处理，不阻塞其他事件。
- 一次性票据：SecureRandom 32 字节 → Base64URL token，库中仅存 SHA-256；消费是单条条件 UPDATE（先标记 CONSUMED 再返回 biz_ref），UNKNOWN/ALREADY_CONSUMED/EXPIRED/REVOKED 可区分；交付与下载按表隔离。

## 3. 验证合同（ZhongshuReliableEventAuditDeliveryContractTest，真实 PG）

| 场景 | 断言 |
|---|---|
| 事务回滚不留事件 | 业务行、outbox、审计一起回滚为零 |
| 提交后至少一次投递 | 提交后 dispatchOnce 领取并投递；已确认事件不重复投递 |
| Sink 失败退避 + 崩溃重领 | 失败 retry_count+1；长租约未被过期不得重领；租约到期可被其他实例重领 |
| 一次性票据 | 首次 CONSUMED_NOW；重放 ALREADY_CONSUMED；未知 UNKNOWN；过期 EXPIRED；明文不落库；交付/下载按用途隔离 |
| 导出任务 CAS | PENDING→COMPLETED 一次成功；终态后重复完成/转失败被拒 |

## 4. 平台迁移目录归属调整

`db/migration/platform/` 与 `db/migration-undo/platform/` 自 P1C 起迁至 `yudao-module-infra`（平台表由 infra 扩展拥有）；`application-pg.yaml` 的 location 字符串不变（classpath 聚合），`ZhongshuFlywayPostgresContractTest` 的 `MIGRATION_COUNT` 常量随之调整。

## 5. 明确不做（P0）

- 不接 Kafka/RabbitMQ/MQ；dispatcher 进程内轮询 + 数据库租约；
- 不做事件 JSON Schema 注册中心；事件载荷由消费端按事件类型解释；
- 不把 Outbox 用于跨库同步。
