# 出图规格与计价 API

## 小程序接口

报价沿用 `GET /app-api/design/v1/generation-price-quotes`，参数为：

- `stage`：`FLAT` 或 `ELEVATION`
- `count`：`1..4`
- `resolution`：`2K` 或 `4K`，不传按 `2K`

响应在原字段基础上增加 `resolution`。规则按 `stage + resolution` 独立解析；4K 没有生效规则时返回价格不可用，不回退到 2K。

`flat-jobs`、`elevation-jobs` 与 `revision-requests` 的请求体增加：

- `resolution`：`2K` / `4K`
- `orientation`：`LANDSCAPE` / `PORTRAIT`

旧客户端创建平面任务缺省为 `2K + PORTRAIT`，创建立面任务缺省为 `2K + LANDSCAPE`。调整请求未传的选项分别继承最近一次立面任务；历史任务没有选项时使用立面缺省值。

项目详情和任务查询响应通过 `imageOptions` 返回服务端冻结值：

```json
{
  "imageOptions": {
    "resolution": "4K",
    "orientation": "LANDSCAPE"
  }
}
```

任务的不可变 `input_snapshot` 同样保存 `imageOptions` 和 `candidateCount`。同一幂等键只有在完整快照一致时才返回原任务，防止分辨率或方向变化后误复用、误计价。

Runtime 的 `/internal-api/design/v1/ai-jobs/{jobId}/inputs` 在快照含规格时原样返回 `imageOptions`；输出上传票据 `maxBytes` 为 20 MiB，与 AI 结果校验上限一致。

## 管理接口

- `GET /admin-api/design/v1/generation-price-rules`
- `POST /admin-api/design/v1/generation-price-rules`
- `PATCH /admin-api/design/v1/generation-price-rules/{ruleId}/retire`

新增规则请求：

```json
{
  "stage": "FLAT",
  "resolution": "4K",
  "unitPointCost": 100,
  "minCount": 1,
  "maxCount": 4,
  "effectiveAt": "2026-09-29T12:00:00Z",
  "expiresAt": null
}
```

`unitPointCost` 必须是 `1..1000000000` 的整数，数量范围必须落在 `1..4`，结束时间必须晚于生效时间。价格调整通过新增规则完成；停用只改变规则状态和版本，历史任务仍使用已冻结的 rule ID、版本、单价和总价。

权限为 `commerce:generation-price:query` 与 `commerce:generation-price:manage`。
